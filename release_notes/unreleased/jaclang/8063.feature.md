- **Front end: the source printers moved off the tree nodes**: `Module.unparse`, `Module.format`, `UniNode.unparse`, `Token.unparse` and `UniNode.to_dict` are gone from `jac0core/unitree.jac`. Rendering Jac source is now `unparse_module(mod, requires_format=True)` and `unparse_node(nd)` beside `UnparsePass` in `jaclang.compiler.passes.tool.unparse_pass`; the whole-module formatter is the `format_module(mod)` that `jac_formatter_pass` already exported, and the node dump is `node_to_dict(nd)` beside the other tree printers in `jac0core/treeprinter.jac`. There is no forwarding method left behind: `unitree` is on its way into a sealed native artifact, and these five could never go with it. `unparse`/`format` orchestrate `NormalizePass`, `UnparsePass` and `format_module` through lazy imports a sealed artifact has no Python left to satisfy, and node rendering reads `gen.jac` -- a `CodeGenTarget` field, and `CodeGenTarget` lives in `jac0core/codeinfo.jac`, which carries LLVM binding and estree handles and imports `unitree` back, so it can never share a native unit with the tree. Rendering behaviour is unchanged, including the dispatch (a node a codegen pass already rendered answers with `gen.jac`, a token with its value, anything else joins its kids) and the annexed-source filtering `Module.unparse` did for `.impl.jac` / `.test.jac` statements.
- **Front end: `unitree`'s native closure is measured, and it is three modules**: compiling `jac0core/unitree.jac` under the seal's own options drags in only `constant.jac` and `srcloc.jac`, both already at zero seams. `codeinfo`, `treeprinter` and `helpers` never enter the native unit, since `unitree` reaches them through typing-only or function-local imports. A new gate, `tests/compiler/passes/native/test_unitree_seal_census.jac`, pins that closure membership, checks the compile really produced native IR (so a zero-seam reading cannot mean "not reached"), and holds an exact per-seam waiver list naming what blocks each remaining one.
- **Front end: eight `unitree` methods now lower natively**: `insert_kids_at_pos` and `set_kids` build their kid list with the typed accumulate-and-extend form `add_kids_right` already used instead of a spread literal; `_get_impl_resolved_body` returns a typed `list[UniNode]` from a flat resolve-then-collect rather than a bare `list` through a nested ternary, which lets the isinstance filters in `get_has_vars` and `get_methods` lower with it; `codespace` walks from `self` instead of special-casing it with a duplicated check, since attribute access on a narrowed `self` does not lower (the Module rule keeps its old scope, so every node gets the same answer); `tail_return_expr` binds the narrowed lambda body and the single statement to locals before reading through them; `resolve_relative_path_list` iterates a list rather than a tuple literal; and `event_trigger_type_names` splits the mangled trigger into a local. Together with the printer split this takes `unitree`'s closure from 47 seams to 34.
