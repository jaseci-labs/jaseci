- **Native marshalling: accessor fields are reachable through the bridge**: after #8074 removed accessor-only fields' data slots, a Python-side read of a `{ getter; }` field on a marshalled native object raised `AttributeError: 'CodeLocInfo' has no field 'mod_path'` -- the bridge only resolved names against the struct layout, so `unparse_module` on a sealed parse's Module could not even read its location. The layout now advertises, per class, the accessor symbol its dispatch binds (the same body the vtable slot holds), the seal exports those symbols from the artifact and proves each resolves in its load canary, and `NativeStructView` routes reads through the emitted `Cls.field.__get__` body -- marshalling the result exactly as a data field of that type would, including archetype-returning, str-returning, and optional accessors -- and stores through `Cls.field.__set__`. Dispatch is virtual: a vtabled receiver is re-keyed to its runtime class via the class-name constant in vtable slot 0, so an overridden accessor (e.g. `sym_name` on `NameAtom` vs `AstSymbolNode`) runs the right body even through a base-typed view. An accessor whose body ships as a waived abort stub is dropped from the advertised table, so reading it keeps raising the same `AttributeError` instead of aborting the process, and genuinely unknown names keep the existing error shape. Plain data-field reads pay nothing new.
