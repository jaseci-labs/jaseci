- **Native: marshalled views read what the layout could not describe**: three metadata gaps left Python-side consumers of native trees reading wrong shapes. The layout's element keys did not survive optional (`(list[X] | None)`) or union-element (`list[(A | B)]`) annotations -- and even present keys were dropped at the optional unwrap -- so such list fields marshalled their elements as bare ints; an opaque generic slot (`has held: T`) decoded its object pointer as text instead of resolving it through the rc header's class-name stamp, the same authority `get_struct_view` re-keys views with; and the view's `keys()`/`items()` mapping helpers shadowed real node fields (`Import.items`) while having no consumers, so they are gone (`["field"]` and `in` remain). The pointer-store test also catches up with the marshalling rework's landed semantics: a store to a known pointer field still raises, while an unknown name lands on the view's Python overlay as annotation state instead of raising.
