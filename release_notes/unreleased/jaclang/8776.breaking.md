- **`del` follows one rule on every backend**: `del T` destroys every graph object `T` denotes, then, when `T` is a location, releases that location exactly as Python would. A node held in a dict entry, a list slice or an attribute slot is destroyed by `del` of that location, as a node held in a name already was; `del L[i:j]` no longer skips destruction by accident. Value targets such as `del [edge a->:E:->]`, `del [a-->]` and `del stale_edges(a)` are accepted and strict, `del a, b;` is accepted, and `del` of a value whose static type can never yield a graph object is the new error E1131. A destroyed object is dead, not gone: connecting to it, spawning on it or visiting it raises, and a walker whose queue already holds it skips it. To drop a reference without destroying what it holds, rebind it (`index["k"] = None`).
