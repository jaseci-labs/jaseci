- **Fix: Resilient startup when another jac process holds the project database**: Every jac process keeps a long-lived transaction open by design, so a second `jac start` used to die replaying schema DDL behind it: a raw `PgWireError` `55P03` dict with an internals traceback. Startup now stamps a schema fingerprint in `kv_state` and skips DDL entirely when the schema is current, so the common boot path never competes for table locks. When DDL is needed, connections carry a `jac:<pid>:<cmd>` identity: backends whose owning local process has died are reaped automatically and the DDL retried, while live conflicts raise a `SessionConflictError` naming the blocking pid, command, and start time. `jac start --takeover` explicitly evicts every other session on the project database. Known database errors (lock timeout, out of connections, connection lost) now render as an actionable message plus hint instead of a traceback (`JAC_DEBUG=1` restores the traceback), and the embedded Postgres is provisioned with `max_connections=256` (was 64) so a default 128-worker `jac test` fan-out cannot starve interactive commands.
