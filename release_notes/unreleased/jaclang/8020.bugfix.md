- **Fix: Sessions no longer idle inside open serializable transactions**: Every jac process used to hold an open SERIALIZABLE transaction for its whole lifetime, which pinned Postgres SSI predicate-lock reclamation cluster-wide: SIREAD locks accumulated monotonically (about 1,300 per minute under a browsing workload on the docs site) until the shared pool overflowed with `53200 out of shared memory`, taking every serializable transaction down with it. Transactions are now scoped to units of work: request execution refcounts active units on the shared session and the last unit out commits and closes the transaction, so a process at rest holds no open transaction and predicate locks retire continuously. The store gains a `REPEATABLE READ READ ONLY` tier (zero predicate locks) for declared read paths, the embedded server provisions `max_pred_locks_per_transaction=1024` headroom plus a five-minute `idle_in_transaction_session_timeout` backstop that disconnects any regressing process (the store heals `25P03` disconnects transparently), and `53200` now renders as an actionable message naming the likely pinning session.
