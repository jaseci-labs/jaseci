- **Fix: a deploy no longer provisions a namespace before checking its pinned jac runtime**: `KubernetesTarget.deploy` resolved `[project] jac-version` inside `generate_manifests`, which runs after `DatabaseProvisioner.provision` has created the namespace and the databases, and after the host client build. A pin naming an unpublished release, or a release publishing neither the pod binary nor the host-runnable one that seals the `.jab` (#7989), therefore failed minutes in and left a half-provisioned namespace behind. The runtime is now settled in a `runtime` phase before provisioning, so those errors surface immediately with nothing to clean up. An exact `==` pin still resolves without listing releases as before, and the preflight fetches the release record, which is what catches a version that was never published. The binary and admin-console caches are also keyed by version, so two pinned versions no longer evict each other and force a full re-download on every alternating deploy.
