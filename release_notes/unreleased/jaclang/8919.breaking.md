- **Regions have one model on every backend (#8913, PR #8919).** `in r { }` now has dynamic, thread-scoped extent natively, as it already did on the Python backend: every archetype, node, and edge constructed while the open is active on the current thread lands in `r`, including allocations made by helpers the open calls. Native user code previously got lexical extent (only constructor calls written inside the braces were arena-allocated), while the compiler's own kernel modules got dynamic extent through a path-gated second implementation; both are gone. Consequences: a helper's result stored outward from an open is now `E1307` (call results made under an open are region-rooted unless the callee receives the handle); worker threads spawned by `flow`/`thread_run` start with no current region; `managed(T(...))` constructs on the managed heap regardless of the current region and is the allocation-side exit for process-lifetime bookkeeping; `region_of(x)` is a declared builtin; and the walker growth rule is the same mechanism (ability dispatch enters `region_of(here)`). Inferred anonymous regions are now real `in Region() { }` opens produced by `RegionInferPass`, so their `drop` hooks fire on the Python backend too. The native arena is a Jac kernel unit (`runtime/region_native.jac`) linked like the OSP kernel; native codegen emits no arena IR beyond the thread-local slot, and the four raw-memory intrinsics (`__mem_load_i64`, `__mem_store_i64`, `__atomic_xchg_i64`, `__mem_call_dtor`) are reserved names.
