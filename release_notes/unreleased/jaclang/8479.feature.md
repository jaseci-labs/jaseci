- **byLLM: per-call usage during a streaming ReAct loop (`usage_step`)**: a new `usage_step` `StreamEvent` fires once per individual LLM call in a `stream=True, logging=True` tool-calling invocation — the main ReAct iteration, the final-answer restream, and the recovery call all get their own event, shaped identically to the existing `usage` event so both can be parsed with the same code. Previously usage was only visible once, in a single aggregate after the entire invocation finished, so a caller enforcing a per-turn budget could only discover an overrun after the whole (possibly many-call) turn had already run. Correctly attributes usage when auto-compaction interleaves with a react-loop call in the same iteration, rather than reporting only the last recorded entry. `IterationContext` (used by the existing `on_iteration` hook) also gains `total_cost`, the real cumulative cost across completed calls, alongside the existing `total_tokens`.
