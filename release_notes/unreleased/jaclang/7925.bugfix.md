- **Fix: fail-open codegen cluster -- silent drops, block-scoped `let`, `len(dict)`, `dict.get` None-identity, ES `match`**: client statements with no ECMAScript lowering (e.g. `del`, and formerly `match`) are now hard errors (`E5017`) instead of silently vanishing from the bundle while the build stayed green. `match` gains a full ES lowering (guarded if-chain over a cached subject -- values, singletons, wildcards, captures, or-patterns, sequences with star, mappings with `**rest`, class patterns, guards), verified byte-identical to the Python backend and enforced cross-backend by the equivalence suite. Branch-first assignments (`if {x=..} else {x=..} return x;`) now bind function-wide like the symbol table says instead of emitting a dead block-scoped `let` per branch and throwing `ReferenceError` -- covering while/for bodies, try/except, module entry blocks, walrus conditions, and mixed destructuring. `len()` dispatches on the argument's type (`dict` -> key count, `set` -> `.size`, unknown -> runtime helper) instead of always emitting `.length` (undefined on objects and Sets). `dict.get()` misses are a real `None` on every backend: the ES emitter routes through a membership-checked runtime helper defaulting to `null` (stored `None` values are also returned as stored, never replaced by the default), and the native emitter returns the real optional representation instead of fabricating a zero of the value type. None comparisons on the client lower to loose equality so a JS `undefined` (no-return functions, empty pops, host interop) can never impersonate a present value. Native cleanups in the same family: `-1 is None` is no longer true (leftover marshalling sentinel), `list.index` misses raise `ValueError` instead of returning `-1`, `setdefault()` with no default inserts a real `None`, bools print `True`/`False`, and printing an optional renders `None` or the payload instead of nothing. Checker: `x == None` no longer raises a spurious `E1110` (it had been steering users toward `is None`, the broken spelling), and `case _:` draws no warning noise. Derived-archetype client constructors now call `super()`, fixing `ReferenceError` on subclass instantiation.
