- **Composite keys in graph filters, for keyset pagination**: A filter predicate may now compare a tuple of declared field names against a tuple value of the same arity -- `[chan ->:Posted:-> [?:Msg, (at, seq) < (cur_at, cur_seq)]]`. A feed keyed on a timestamp alone drops or repeats rows whenever two entries share a timestamp; the tiebreak needs this. The shape stays inside the closed sublanguage `E5094` defines: the same operators, the same push-to-SQL guarantee, one more arity. It compiles to a SQL row comparison, uses promoted columns when they are declared and the raw jsonb path when they are not, and matches lexicographically in object space.
- **Non-pushable filter predicates are applied instead of dropped**: `compile_query` reported predicates it could not push, and the planner logged that they were "re-checked on the materialized results" -- but no re-check existed, so a residual predicate silently returned unfiltered rows. Residuals on the final hop are now applied to the materialized results. A residual on an intermediate hop, which the id-space pipeline cannot filter after the fact, is logged at error level rather than passed off as handled.
