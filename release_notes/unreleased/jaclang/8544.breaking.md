- **Fixed-width numerics become real types with one contract across `jac check`, the server, native, and client lanes** (#8532): `i8 u8 i16 u16 i32 u32 i64 u64 f32 f64` are no longer `int`/`float` with a width hint. Conversions follow one value-preserving lattice (widening implicit, everything else the checked cast `T(x)` or the modular `T.wrap(x)`); int literals are range-checked at check time (`E1126`); narrowing and same-width sign changes are refused (`E1127`); operators need unifiable operands (`E1128`); unary minus on unsigned is refused (`E1129`). Sized arithmetic traps with `OverflowError("integer overflow")` on every lane (plain `int` and `float` arithmetic is unchanged), including the server lane where the ten names are now real `int`/`float` subclasses; `u*` types lower as unsigned natively (`udiv`, `lshr`, `icmp u*`, unsigned overflow intrinsics) and `f32` rounds to binary32 after every operation; the client lane gains `_jac.fw` helpers with `i64`/`u64` on `BigInt` (a 64-bit value serializes as a JSON number when it fits in 2^53 and as a string otherwise). `T.MIN`/`T.MAX` and the `wrapping_add/sub/mul/neg/shl` builtins are new. **Breaking:** code that passed `int` into sized (typically extern `i32`/`u64`) parameters now needs the cast (`i32(n)`); `u*` values are unsigned (`u8(255) >> 1 == 127`, `~u8(0) == 255`); server-lane overflow that used to wrap or grow silently now raises. The ten names, widths and signedness are defined once (`jac0core/scalars.jac`, surfaced through `JAC_TYPE_REGISTRY`); `na_type_spec`, `FOREIGN_SCALARS`, `INT_LIKE_WIDTHS`/`FLOAT_LIKE_NAMES` and the pass-local name lists are gone. JIR format version 22.
