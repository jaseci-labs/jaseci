- **Native: `is` / `is not` against an option answered a different question** (issue #8150): `_codegen_compare_link` lowered `KW_IS`/`KW_ISN` only when both operands reached it as pointers, plus a tag test when one side was a literal `None`; everything else fell through to `return self._to_bool(left);`. A `T | None` value is a `JacOpt` -- a presence tag beside the payload -- and not a pointer, so `tab is self` compiled to "is `tab` set?" with the right operand discarded, and `KW_ISN` took the same fallback without negating, making `x is not y` and `x is y` produce the same value. Identity over an option is now emitted directly (both absent, or both present with equal payloads, negated for `is not`; an option against a plain reference matches when the option is present and the payloads agree). This is what broke `UniScopeNode.get_enclosing_captures`, whose guard is `(tab is None) or (tab is self) or not isinstance(tab, (...))`: with `tab is self` collapsing to "tab is set" the guard skipped every symbol, so on the sealed artifact every lambda captured nothing.
- **Native: the narrow the checker computed is now consulted, not just `Expr.type`** (issue #8150): `get_type_of_expression` stores the *member's* type on `Expr.type` and returns the narrow to its caller, so a consumer reading only the field never sees it. `Name` is the exception -- a symbol's narrow is folded into the stored type -- which is why local narrowing has always worked natively and nothing else has. The backend now asks for the narrow (memoised per node) wherever it resolves a receiver or retypes a read, so `stmts[0].expr` after `isinstance(stmts[0], ExprStmt)` finds a field instead of failing the whole `AtomTrailer`, `self` resolves against the class an enclosing `isinstance` narrowed it to rather than the declaring archetype, and a reference expression can be retyped at all. The third storage a union can pick is handled with it: all-pointer members keep the first member's pointer layout instead of boxing, so narrowing to a container member is a bitcast, taken only when the narrowed element type is named. Two related crashes go with it: `_typed_elem_llvm_of` read `expr.type.private.type_args` unconditionally and a field read off a *joined* narrow (`item.values` over `TupleVal | ListVal`) is a `UnionType`, which carries no `private`; members that agree on the container shape agree on its element type, so the first member carrying type arguments now answers for the union. Beyond the shapes it was written for, this retires eight seams `unitree`'s native census had waived as backend gaps -- the six `access_type` accessors, `Import.is_jac`, and `ModulePath.string_path_value` -- taking the module from 28 seams to 20.
- **TypeCheck: `isinstance(x, list)` over a `Sequence[T]` member keeps `T`** (issue #8150): `_filter_union_for_isinstance` keeps the union members the isinstance target is a subtype of, so a member the relation runs the other way for drops out and the narrow falls back to the bare target class. `isinstance(lam_body, list)` over `Expr | Sequence[CodeBlockStmt]` therefore narrowed to bare `list`, with no element type -- enough for the checker to accept a copy, not enough for the native backend to know which list flavour the slot holds. A value that is both a `Sequence[T]` and a `list` is a `list[T]`, so the member's type arguments now carry onto the target class when it declares the same number of parameters; the container protocols are exactly this shape (`list` is a `Sequence`, `dict` a `Mapping`). Narrows whose target is already parameterised, declares no parameters, or takes a different number of them are unchanged. This is the shared evaluator, so the sv/bytecode codespace narrows the same shape the same way.
- **unitree: six workarounds retired** (issue #8150): each of the rewrites #8052 needed to seal `unitree.jac` natively is a receipt for one of the defects above, and all but one is now gone. `get_enclosing_captures` gets its `not isinstance(tab, (Ability, ImplDef, LambdaExpr, Test))` back, `insert` its nested access-resolution ternary, `tail_return_expr` its in-place `stmts[0]` narrowing, `_fix_store_ctx` its single joined `TupleVal | ListVal` arm (and the `_fix_store_items` helper is deleted outright), `codespace` its narrowed-`self` fast path, and `LambdaExpr.postinit` its defensive `list` copy -- the one safety property the dialect had traded away, so a lambda no longer aliases the list its caller handed over. `Archetype._get_impl_resolved_body` keeps its flat body and now says why: the ternary lowers, but `Archetype.body` is the `T` of a generic whose layout is type-erased, so the narrow cannot name the element type and the typed local is what pins it.
