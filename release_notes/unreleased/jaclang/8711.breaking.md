- **The scale runtime pools its Postgres connections and runs read-only units on the read tier** (#8711): each served request used to dial a fresh wire connection (TCP + SCRAM per request) and run its whole volume at SERIALIZABLE. Connections are now parked in a per-process pool keyed by conninfo (`JAC_DB_POOL=0` disables; `JAC_DB_POOL_MAX`, `JAC_DB_POOL_IDLE_S` tune it), so `pg_stat_activity` shows long-lived sessions instead of per-request churn. Walkers and functions the process has never observed writing open `REPEATABLE READ READ ONLY`; the first write re-runs the request at SERIALIZABLE via the conflict loop and records the unit as a writer for `JAC_DB_RO_WRITER_TTL_S` (300s default; `JAC_DB_RO_UNITS=0` restores SERIALIZABLE everywhere). Write paths keep SERIALIZABLE verbatim and version OCC on upsert is unchanged. The provisioned Kubernetes Postgres also changes its server arguments (shared_buffers 256MB, work_mem 8MB, wal_compression, max_wal_size 2GB, random_page_cost 1.1) and gains container resources, all overridable via `[scale.database]`; and the microservice gateway now serves the client SPA at `GET /docs` when the app ships a client bundle, keeping Swagger there only for headless fleets. The writer record is per process, so each replica re-learns its writing units once per TTL window (all at once on a rolling deploy); a higher `JAC_DB_RO_WRITER_TTL_S` trades fewer re-learn passes for a transiently demoted read path staying at SERIALIZABLE longer.
