- **Fix: `as` cast no longer swallows the rest of the expression**: `x as int == 0` parsed as `x as (int == 0)` -- the comparison was absorbed into the cast's type expression and the whole expression silently evaluated to `x`, so the check read correctly but behaved backwards in every codespace. The cast now binds tighter than comparison and logical operators (and still looser than arithmetic, so `a + b as T` remains `(a + b) as T`): `x as int == 0` means `(x as int) == 0`. The cast target is now a proper type production -- a dotted/subscripted type reference or a union like `int | None` -- so an operator after the target (`x as int + 1`) is a syntax error instead of being silently absorbed; parenthesize the cast to operate on its result. Independently, the checker now rejects a cast target that is not a type (a value, comparison, or literal) with the new `E1044`, which also catches the explicit form `x as (int == 0)`.
