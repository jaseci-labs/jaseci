- **`jac test` orders work by measured cost, and can stride a file across workers**: the runner records what each test file cost into the project cache (`.jac/cache/test-durations.json`) and, on the next run, dispatches longest-first instead of in directory-walk order. A file listed in `[dev] test_shard` (or `JAC_TEST_SHARD`) is additionally split into shards that each import it once and run every Nth registered test, so a single expensive file no longer pins one worker. Striding is opt-in because nothing in a test file declares that its cases are independent: a case that leans on one before it -- an in-module memo, a process-wide file descriptor -- changes its verdict when the stride moves it, and a runner may not do that silently. With no recorded costs the plan is exactly what it was before, so a cold checkout and a first run are unchanged.
