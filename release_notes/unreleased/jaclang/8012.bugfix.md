- **Fix: `jac scale destroy` no longer leaves the namespace behind**: the kubernetes teardown stopped after sweeping the label-managed fleet and destroying the observability stack, so the bundle PVC, the app secrets and ServiceAccounts, the provisioned postgres StatefulSet and its data volume, the ingress controller and the namespace itself all survived a destroy, and the `--component` argument was accepted but ignored, so asking for one component tore down every workload instead. Destroy now runs the whole teardown as an ordered, fault-isolated set of phases owned by the base target, with the fleet sweep contributed by the fleet-aware subclass, so workloads still go first and their pods drain off the bundle PVC finalizer before the volume sweep behind them. One phase failing (a forbidden ClusterRole delete under namespace-scoped RBAC, a flaking apiserver) no longer aborts the run and strands the namespace delete that would have reclaimed everything; failures are reported once at the end and are fatal only if the namespace survived them. The teardown also binds its Kubernetes API clients once, so the namespace is deleted in the cluster the target was configured for rather than in whatever the ambient kubeconfig current-context happens to be.
