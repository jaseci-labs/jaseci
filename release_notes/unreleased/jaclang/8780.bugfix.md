- **Fix: Release builds bundle the LLVM shim under its canonical name**: On the release channel `zig build` passes mkpayload a prebuilt shim named `libjacllvm-<platform>-<hash>.so`, the content-keyed asset the `deps` prerelease carries, and the payload assembler staged it into the site under that source name. Nothing looks for it there, so the JIR seal failed on every module that needs LLVM (`import from c`) and no release binaries were produced. The site-relative shim path now has a single authority shared by the staging copy and the strip step, so the incoming path's name no longer matters and a misplaced shim fails at the copy instead of surfacing hundreds of modules later as "Could not locate the LLVM shim".
