- **TypeCheck: a typed declaration inside a block keeps its annotation**: Jac locals are function-scoped, but only bare assignments were bound that way; a typed declaration inside a `while`, `if`, `for`, or `try` body was inserted into that block's symbol table instead. One variable therefore became two symbols -- the declaration on the block, and a second one on the function created by whichever assignment rebound the name first -- so `item: (A | B | None) = None;` in a loop body followed by `item = pa(c);` / `item = pb(c);` in the arms of an inner `if` rejected the second arm with `E1001: Cannot assign B | NoneType to A | NoneType`, the first arm's type. The declaration now lands in the enclosing function scope, the same scope the assignments bind in, so every rebind is checked against the declared annotation and hoisting the declaration out of the block is no longer a workaround. Assignments the annotation does not admit are still reported, and module and archetype bodies keep their block scopes so version-guarded stub declarations continue to resolve per branch.
- **Newly diagnosed by the above (both were silently accepted before)**: a block-scoped declaration's annotation now holds *after* its block, since the name was always live there and only its type was being lost (`if c { z: int = 1; }` then `z = "oops";` is `E1001`); and two sibling blocks that each declare the same name are one variable, so the second declaration is checked against the first (`if c { v: (A | None) = A(); } else { v: (B | None) = B(); }` is `E1001`). The second shape is a redeclaration, which the language reference specifies as `E0064` ("a typed declaration after the name has already been bound in that scope"); `E0064`'s trigger is still limited to names that rebind an *outer* binding, so today it surfaces as an assignment failure at the second declaration. Give each variable its own name, or hoist a single declaration above the blocks.
- **Parser: `parse_assignment_with_target` returns `Assignment`**: the declared return was `CodeBlockStmt` while the single return path builds an `Assignment`, which is what `IterForStmt.count_by` requires. The over-wide signature only surfaced once the `step_assign: Assignment;` declaration in `parse_iter_for` stopped being stranded on its block. The generated `jac.spec` is byte-identical.
