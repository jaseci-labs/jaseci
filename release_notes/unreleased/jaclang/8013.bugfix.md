- **Fix: a deploy installs the app's dependencies before the host client build**: The client bundle is built once on the deploy host and shipped to the gateway pod, and that build imports the app's whole module graph to find its client exports. The host was never given the app's `[dependencies]` though, so any client entry that transitively reaches a module importing a declared package died with a raw `ModuleNotFoundError` (`psycopg`, `sqlalchemy`, anything pip-backed). This was survivable while the host build was best-effort and the pod rebuilt the bundle at boot, where the deps do exist; once that fallback was removed to fail the deploy fast on a broken client build (#7936), the same apps could not deploy at all. The deploy now runs the app's own installer against the staged project, with the binary that runs the build, so the host build env matches what the pod gets at boot. A dependency the host cannot resolve stays a warning rather than a new way for a deploy to fail, since the build host is not the pod's platform; if the build then dies, the error names the failed install instead of leaving a bare import traceback.
