- **Compiler: headerless (`--memory nogc`) code is correct for the everyday owned shapes**: a named `own` local moved into an own field, an optional own field, an inline-flattened field, or a constructor argument is consumed at the move (the checker stamps `Module.own_move_sites`, the backend consults it through one primitive), optional own fields tear down with their parent, own parameters are dropped by the callee, overwriting an own field drops the old value, and every one of these static drops applies only in the owned world (a nogc-enforced, non-kernel module). The owned-list layout is decided once from the element type (inline only for a closed-world leaf archetype with no heap slots), so `list[own T]` and `list[T]`, generic bodies and their callers, and borrow returns agree on it; `pop`, `insert`, `del`, and `extend` on an owned list move payloads by value. See #8984.
- **Language: `take(place)` and `swap(&mut a, &mut b)`**: two builtins that move a value out of an optional owned place (leaving `None`) and exchange two places, on every backend. E1316 rejects moving a heap value out of an owned slot without `take()`; E1317 rejects moving an element out of an owned list (use `pop()` or a borrow).
- **Language: receiver modes for methods**: the checker infers whether a method reads (`&self`), writes (`&mut self`), or, when written as `def m(self: own T)`, consumes its receiver. A mutating call while a shared borrow is live is E1303, on an `imm` binding E1309, through a shared borrow E1318; a consuming call moves the receiver. An explicit `self` in an obj/node/edge/walker method is admitted only to declare its mode (E2015 otherwise).
- **Checker: the structural loop-move rule is gone**: a binding moved inside a loop and re-assigned before the back-edge is clean; the CFG dataflow already proves the moved-in-a-previous-iteration case.
- **Dev loop: a stub catalog shipped in the binary is validated against the checkout under the dev-source reroute**, so an edit to `jac_builtins.pyi` rebuilds the dev catalog instead of silently typing new builtins as Unknown.
- **Language: the `lin` marker**: `x: lin T = ...` (and `lin` parameters) declares a must-consume owned binding. It moves, borrows, drops and lowers exactly like `own`, and the checker adds a must-analysis over the control-flow graph: a path on which the binding reaches the end of its scope unconsumed is E1305.
- **Language: container stores are moves**: a named `own` archetype binding appended or inserted into a list, stored as a dict value, or placed in a list literal is moved into the container (a later read is E1301); the E1406 fence now admits fresh and named archetype elements for lists and dict values, while borrowed values, field reads and sets of archetypes stay fenced. Under headerless codegen a dict of owned values drops an overwritten value at the store and a deleted value at `del`, and `pop(key)` hands the value to the receiver.
- **Compiler: errors propagate without an unwinder under the nogc profile**: every function carries an inferred raises effect (stamped on the tree for tooling), a `raise` in an enforced module stores into a shared error slot and returns, each call to a raising function is followed by a check that dispatches to the enclosing `except`, runs `finally`, or drops the frame's owned locals and propagates. A raising call an entry block does not handle is E1407 at compile time.
- **Dev loop: a dev checkout never parses through the shipped native compiler kernel**: under the dev-source reroute the kernel lookup stops at the checkout, so edits to the lexer, parser and node classes take effect immediately.
- **Dev loop: a dependency tree owned by another program is adopted unless it is an untyped Jac tree**: stub trees are complete as they are, and a locally compiled view never replaces the foreign program's live tree.
- **Tooling: inlay hints for inferred ownership facts**: the language server publishes hints for the inferred ownership state of unmarked locals, view bindings, receiver modes, and raises effects, produced by one `inferred_hints` walker in the compiler that `jac explain memory` shares.
- **Runtime: a buffered possible root that reaches a zero count is destroyed at once**: with the cycle collector on by default, an object that had been buffered as a possible cycle root and then dropped to zero is removed from the roots buffer and reclaimed immediately (drop hook included) instead of waiting for a collection that a short program never runs; the collector's root passes skip the slots such a release empties.
- **Checker: unmarked locals infer their ownership state under enforcement** (#8984 rule 1): a call, container literal, f-string, concatenation or `own` copy is `own`; a string literal is `imm` (or `own` once rebound); a field or element read (`c.name`, `xs[i]`, `self.head`) borrows its root, mutably when the root allows it and the local is written through; `&place` and reborrows tie to their owner; a conditional whose arms agree takes their state, and one whose arms disagree stays `E1401`. Contract positions stay explicit in every module. A str method called on a borrowed element (`p.upper()`) now resolves as str for the container fence: the type system's `LiteralString` overloads are str to the ownership checker.
- **Diagnostics: `E1406` says what to write**: the message names the value, why it cannot enter the owned world (a borrow of `parts`, an `imm` value, a read of a place owned by `c`, a retaining builtin) and the destination, and the help names the idiom that fits the site: `out.append(own p)` copies a str, `take(place)` moves an element out, `for p in parts` iterates by value, or build the element fresh. `own <expr>` on a str is accepted by the fence as the copy-in idiom.
- **Checker: builtin container mutators are `&mut self` methods**: `append`, `insert`, `pop`, `remove`, `clear`, `extend`, `update`, `sort` and the rest now take part in the receiver discipline, so calling one through a shared `&` borrow (a `&T` parameter, a loop borrow, or a local that borrowed a container field) is `E1318`, exactly like a user method that writes `self`. Before, only user methods were checked and a shared borrow could grow a container.
- **Build: the launcher stub and the native compiler kernel build through `jac build --native`**: the zig build script no longer invokes the removed `nacompile` verb, and a `--lib` build no longer refuses Python-only demotions in its closure (a shared library runs those in Python; only a self-contained executable cannot). `jac build --native --target-triple <triple>` publishes the triple to every compile-time consumer (clib file names, platform decisions) for the duration of the build, the way the wasm builder already did; tests that cross-target use `push_native_target`/`pop_native_target` from the compile-options module instead of the retired environment variable.
- **Compiler: a headerless build never drops through a borrow local**: a local whose state is a borrow (inferred from a field or element read, or written as `&place`) is exempt from the scope-exit and overwrite drops, so `it = xs[0]; it.name = ...` mutates the element in place instead of destroying it under `--memory nogc`. Before, only module-global aliases were exempt.
- **Compiler: the owned-list layout is decided once from the element type, whatever is lowered first**: an entry-block global typed before the element archetype's struct body was registered used to be laid out inline (array-of-structs) while every later use of the same list type chose the pointer layout, so a list built in one place and read in another was garbage. The decision now derives the element's field types from the declaration when the body is not registered yet, so every site agrees.
