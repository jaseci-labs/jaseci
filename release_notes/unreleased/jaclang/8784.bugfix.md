- **Fix: Type-only imports are checked instead of emitting a dead ESM specifier**: Import bindings now carry a kind (value / type / both) inherited from whatever they resolve to, so a name that exists only for the checker -- a TypeScript `interface` or `type` alias in a `.d.ts`, or a jac `type` alias -- can no longer be brought in by a plain `import from`. That used to pass `jac check` silently and then emit a named specifier the browser refuses at link time, taking the whole client module graph down with no diagnostic upstream. Two new blocking errors replace the silence: `E1131` when a type-only export is reached by a plain import (move it to `import type from <module> { Name }`), and `E1132` when an `import type` binding is used in value position (a call, an attribute read, an `isinstance` argument, a decorator, a base class, an assignment). Annotations, `has` field types, generic arguments, `as` casts and `type` alias right-hand sides stay legal. See [Type-Only Imports](../../reference/language/types-and-values.md#type-only-imports-import-type).
