- **A bare clone's `[dev] jaclang_source` no longer breaks the released binary**: a repo can carry a `[dev]` stanza so contributors run the in-tree compiler, and the `jac` binary honoured it even in a tree that had never been built. A plain `git clone` has the compiler's source but not its gitignored typeshed stdlib stubs (`zig build fetch-typeshed` materializes them), so the first compile inside such a tree, `jac install` in the in-tree jaclang.org site for instance, died with `FileNotFoundError: Stub file not found at .../vendor/typeshed/stdlib/typing.pyi`. The launcher now refuses to reroute into a checkout with no typeshed stubs: it prints one line naming the missing stubs and the build step that produces them, and the bundled compiler serves the run. A linked dev binary (`zig build -Ddev`) is never refused, since it has no bundled compiler to fall back on, and `JAC_NO_DEV_SOURCE=1` still forces the loop off.
- **`jac check` sizes its worker pool by the memory each worker may reach**: the pool budgeted workers at a 2 GB typical footprint but recycled them only at a 4 GB ceiling (`JAC_CHECK_RECYCLE_MB`), so a cold whole-repo sweep on a 16 GB machine ran four workers that, at the ceiling, out-weighed the machine with the parent, and a CI runner died before any of them retired. Available memory is now divided by the recycle ceiling instead: a 16 GB box runs two check workers, a 32 GB box four, and `JAC_CHECK_JOBS` still overrides.
