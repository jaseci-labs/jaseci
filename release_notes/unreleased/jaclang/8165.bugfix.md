- **Fix: config changes now invalidate the compile cache instead of serving stale modules**: `is_module_cache_valid` short-circuited on file mtimes and returned before ever comparing the module key, and `jac.toml` is not in the set of files it stats. Editing `[placement.pins]` therefore left every mtime untouched, the freshness check passed, and the correctly-computed key (which has always included the pins digest) was unreachable, so builds kept emitting the previous placement. `write_module_jir_cache` also refuses to overwrite an entry that looks valid, so not even a correct recompile could repair it and `rm -rf .jac/cache` was the only cure. The key is now split into a cheap config half, stored in a new `SEC_CFGKEY` section and compared on every cache hit, and the expensive content half, which the mtime path still gates. This covers every config-derived input rather than just pins: project kind, codespace, client kind, service cut, and the codegen fingerprint, including the parts fed by `JAC_OPT_LEVEL`, `JAC_NATIVE_TARGET`, `JAC_NATIVE_DEBUG` and `JAC_RC_DEBUG_CODEGEN`, which no timestamp can capture. Cache entries written before this change stay valid while config is unchanged, so upgrading does not force a global recompile.
