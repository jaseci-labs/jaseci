- **Fix: darwin CI runs the string and bytes primitive equivalence pins**: `test-native-macos` ran the bundled-stdlib equivalence pins filtered to `shutil or path or textwrap or keyword`, so darwin ran no string-primitive equivalence at all and every `prim_str.jac` and `prim_bytes.jac` pin -- `lower`, `upper`, `startswith`, `endswith`, slicing, `join`, iteration, relational compare -- was Linux-only. The native lowering of those primitives is not platform-neutral: `str.lower()` lowers to a per-byte call to libc `tolower`, and the two link paths do not resolve that name to the same implementation, since Linux executables statically link the vendored musl while the Mach-O path binds every undefined symbol to `libSystem`, whose ctype functions are rune-locale driven. The seal's parse parity canary is red on the macos-aarch64 release leg for a divergence in exactly this family, and the seal runs only on push to main, so until now there was no PR-speed darwin signal for any of it.
