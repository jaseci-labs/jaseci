- **Compiler: the graph-shaped compiler (#8744)**: syntax nodes are immutable object-spatial nodes, tree structure and semantic relations are typed edges, the type system is nodes and edges in the same graph, and every pass is a walker. Node fields that passes used to assign (`kid`, `body`, `type`, `sym`, ...) are read through accessors over edges. The jac0 seed tier now lowers the object-spatial subset (`node`/`edge`/`walker`, connect, edge references, `spawn`, `visit`, abilities) so the seed compiler is graph-shaped too. Also fixes the bytecode kernel's quadratic connect (#8743, hash only).
- **Runtime: subtree-fenced `visit:0:`**: front-splicing visits (`visit:0: targets;`) now give walkers true depth-first traversal with enter/exit abilities bracketing each subtree (a node's exit fires when its subtree completes, not when the queue drains). Plain `visit` keeps the legacy queue semantics. The kernel also gained `osp_skip_rest` (suppress the current node's remaining abilities, which is how a walker declines to descend) and a typed-dispatch match cache.
- **Compiler: the tree directs the walk**: `UniNode` carries a `walk_kids` ability triggered on `TreeWalker` (a marker walker every `UniPass` inherits), so the node front-splices its own kids after every walker hook for that node has run. The kernel already orders node abilities after walker abilities, so no scheduling primitive is needed: pass hooks that rewrite `kid` are seen by the expansion, and a walker declines to descend with `osp_skip_rest()`, which suppresses the node's own abilities while still running the exit phase. `UniPass.prune()`/`prune_signal` are removed (use `osp_skip_rest()`), as are the `__jac_post_entry__`/`__jac_post_exit__` kernel callbacks; the three passes that carried an exit tail now declare it as an ordinary ability last in the class body.
- **Compiler: pass hooks are typed OSP abilities**: the `enter_<node>`/`exit_<node>` visitor surface (`accept_enter`/`accept_exit` double dispatch, ~460 generated stubs) is deleted. Passes declare `can enter_x with IfStmt entry { ... }` and the walker kernel dispatches them by trigger type; ability triggers use `isinstance` semantics, so hooks on types with node subclasses carry explicit exact-type guards where the old exact-match behaviour matters. Third-party passes using `def enter_<node>` methods no longer dispatch and must convert to abilities. `jac gen-uni-dispatch` is removed.
- **Compiler: the type system is part of the graph**: every type (`ClassType`, `FunctionType`, `UnionType`, `TypeVarType`, ...) is an object-spatial node, and type composition is typed edges (`TypeOf` from expressions to their types, `BaseOf`/`MroOf`/`TypeArgOf`, `ParamOf`/`ReturnsOf`, `UnionMemberOf`, `BoundOf`, overloads, enum members). Field APIs are preserved through accessors (edges are the source of truth; hot reads memoize per node). Identical class types intern by declaration identity, and the type evaluator is a walker (`expr spawn evaluator` types a subtree on demand).
- **Compiler: graph lifetime and scheduling (WS5)**: `JacProgram.release_module` releases one module's graph -- it severs every edge crossing the module boundary (placement edges to codespace singletons, `TypeOf` edges to interned types, the program root's ties) so the tree is garbage-collectable while the program lives (regression-tested with weakrefs). Pass scheduling speaks edge kinds: writers declare what they produce (`SymTabBuildPass` -> `SymOf`/`Defines`/`InScope`, `CFGBuildPass` -> `CfgSucc`/`CfgTrue`/`CfgFalse`, `TypeCheckPass` -> `TypeOf`, `DeclImplMatchPass` -> `ImplOf`, placement -> `PlacedIn`/`DecidedCodespace`) and hard readers require them; every schedule is validated against these declarations when it is built. After a module's pipeline completes, `FreezeStructurePass` locks its tree: structural mutation (`set_kids`/`replace_kid`/`_role_set`) on a frozen node raises, with `thaw_structure()` as the deliberate escape. `set_parent` no longer fabricates a non-kid edge -- synthesized nodes carry a `_ctx_parent` context reference instead. LSP definition/references already run on `Defines`/`Uses` edges via the symbol accessors.
- **Retired**: `jac gen-uni-dispatch` and the generated visitor surface, `AstTool.pass_template` (emitted templates for the deleted visitor dispatch), `UniPass.term_signal`, and the role-name string bridge.
- **Compiler: `JAC_COMPILER_DIGEST_PIN`**: a developer knob that freezes the compiler-tree digest folded into every JIR's environment key, so an edit to the compiler recompiles only the modules whose own source changed. Unset, behaviour is unchanged.
- **Runtime: light edges**: a field-less, directed edge between unpersisted nodes is an adjacency entry (`NodeAnchor.out_light` / `in_light`, keyed by edge class), not an `EdgeArchetype` plus `EdgeAnchor`. Out-links are strong and in-links are weak, so ownership follows connect direction and a fan-in target never keeps its sources alive. `[x ->:T:->]`, `[edge ...]`, `visit`, `disconnect` and `del` see no difference; a node that is saved materializes its light edges into rows. Edges with fields, undirected edges and edges touching a persistent node are unchanged.
- **Language: the simple hop and `del` on an edge set**: `[x ->:T:->]` with one origin, one direction, an edge class and no predicate, filter or chain lowers to a direct adjacency read (`hop`; `hop0` in the seed tier) instead of a planned query, in both the seed and py lowerings. `del [edge x ->:T:->];` is now a statement form: it deletes every edge of the set without materializing it (`clear_edges` / `clear0`); the direction and type follow the reference, `[edge x -->]` deletes all out-edges. Previously `del` of an edge reference did not compile on either tier.
- **Runtime: no per-write hook on transient archetypes**: `Archetype.__setattr__` is gone; persistence dirty-marking is installed on an archetype only when its anchor becomes persistent (`track_writes`, a generated same-named subclass). The walker kernel takes its scope by parameter (no walk-stack lookup after every ability), front-splicing `visit:0:` is O(len(targets)) on a dedicated stack, and the bytecode driver hands the kernel archetypes rather than anchors (no per-ability unwrapping wrapper).
