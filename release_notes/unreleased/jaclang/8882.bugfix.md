- **Fix: which identity stack owns `/user/*` is now a configuration decision, the core server stores scrypt, and a dev server keeps its signing secret**: the owner of the identity endpoints was a side effect of an import. `get_api_server_class` asked the scale plugin for a server class and answered any `ImportError` in that graph with a DEBUG line and `None`, which demoted the whole API server to the core class. The two classes own different credential stores -- Postgres holding `scrypt$` hashes, and sqlite `.jac/data/main.db` holding unsalted sha256 -- so one transient compile error or half-written cache entry moved `/user/*` to a store with none of the existing rows in it, and every account created before the flip was told its password was wrong while its graph data sat untouched. `identity_owner()` now resolves the owner from configuration alone: `JAC_IDENTITY_BACKEND`, else jac.toml `[serve] identity`, else `auto`, which is the scale identity when the scale package is installed and the core identity when it is not. Nothing about a database's reachability or an import's luck enters it, and a scale stack that will not import raises with the module name instead of quietly serving the other store. The core server also stopped writing unsalted sha256: signup, login, and password change go through the shared `authcrypt` module, and both stacks accept a legacy sha256 row once and rewrite it as scrypt on that login, so accounts written before the migration carry across without a reset. Separately, `[scale.jwt] secret` no longer defaults to a literal shipped to every project: a dev server mints one into `.jac/data/jwt_secret` (gitignored, 0600) and reads it back on later boots, so sessions survive a restart, while a configured secret still wins and a cluster with none configured keeps the placeholder and warns.
