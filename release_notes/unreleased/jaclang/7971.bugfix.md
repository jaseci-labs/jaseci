- **Web-app projects keep pure modules out of the native default**: under the native-preferring default codespace, any markerless module that happened to lower (e.g. a file of numeric design-token globs) was claimed native, turning its client importers' imports into `__na_bind` wasm stubs and silently gutting their ES bodies; the only symptom was a rollup `"X" is not exported` failure on cold builds, and warm caches masked it indefinitely. `native_default_verdict` now refuses markerless modules when `project.kind == "web-app"`, keeping native opt-in there via extern anchors, `[placement.pins]`, or `nacompile`. When ES lowering of a client-pulled module fails and the demote path recovers the build, a dim note now names the module and the first error instead of swallowing them.
- **`postinit` runs in the browser**: the ES backend emitted `__post_init__()` as a method but never called it, so any `obj` relying on `postinit` for derived-state wiring worked in every Python context and was silently dead exactly and only client-side. The generated constructor now calls it as its final statement, and a fields-less archetype that declares `postinit` still gets a constructor (regression test and fixture included).
