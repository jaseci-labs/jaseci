- **Refactor: native brands bind once, at a point the driver owns**: Binding the materializer registers class identities, so when it happens is observable to the type checker and a binder reached at a new point could leave two brands of the same class in play. Binding is no longer left to whichever of first-parse or first-pass-construction wins the race: `ensure_native_brands_bound` is now the only function that reaches the binder, it records which caller got there first, and `frontend._native_parse`, the pass-serving merge canary and the prefix predicate all become consumers that route through it. The driver-owned point is `JacCompiler`'s own construction rather than any single call site, so a compiler cannot be obtained without the brands already being bound.
