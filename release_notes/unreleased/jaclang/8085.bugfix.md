- **Native: an explicit `return` in a `-> None` callable produced unparseable IR**: `-> None` lowers to an LLVM function returning `void`, but `_codegen_return` coerced the returned expression to the function's return type and emitted `builder.ret(val)` regardless, so `return None` became `ret i8* null` inside a `define void`. LLVM refuses to parse that, and the failure is module-wide: the whole compilation unit falls back to the server codespace with `E5020: LLVM IR parsing error`, so nothing in it lowers. Falling off the end of a `-> None` method was always fine, which is why only an explicit `return` with an expression hit it. A void function now emits `ret void`, with the expression still evaluated first so a `return some_void_call()` keeps its side effect.
