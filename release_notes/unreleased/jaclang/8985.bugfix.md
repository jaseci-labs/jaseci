- **Fix: `@jac/mobui` is typed by the checker**: `import from "@jac/mobui"` never resolved (the shim ships as `client_mobui.jac`, the resolver looked for `mobui.jac`), so every mobUI primitive typed as Unknown and cascaded W1100/W1051 through mobile apps and any shared `core/` UI. The resolver now knows the runtime sources by name (`@jac/pwa` had the same gap), and the shim carries a sibling `client_mobui.d.ts` declaring the whole surface, so `View`, `Text`, `StyleSheet.create`, `useWindowDimensions` and friends have real types and an unknown prop on a primitive is E1101 like any other component.
- **Fix: false `E5104` app cycle through a shared helper**: when a service app imported a pure shared module (no walker, node or edge) and the consumer was shared code owned by the workspace's default app, a codegen build reported `App dependency cycle: web -> service -> web` and `jac build` refused the app. The cycle walk asked an unlinked import binding for its source module and got the importing module back, whose own walkers then made the helper look owned. An import binding is never its own source: the linker skips it, and ownership falls back to parsing the resolved target.
