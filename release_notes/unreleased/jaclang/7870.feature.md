- **Refactor: string indirection sweep (fat-descriptor step 1)**: every raw libc `strlen`/`strdup`/`strcmp` on Jac strings in the native backend now routes through the `__jac_str_*` helper layer (`__jac_str_len`, new `__jac_str_cmp`/`__jac_str_dup`/`__jac_str_len_raw`, and the `_str_alloc`/`_str_finish` producer bookkeeping), so the descriptor flip changes helper bodies instead of ~150 call sites. Pure refactor with byte-identical output across gc modes, pinned by a new IR-cleanliness gate (`test_str_helper_layer.jac`) plus the `own_strops` oracle; producers that previously skipped the length stamp (argv, `input()`, `str(int)`, `format`, file reads, split tokens, float repr) now stamp it, upgrading their `len()` from O(n) strlen to the O(1) header fast path.
- **Refactor: JacStr descriptor behind ABI shims (fat-descriptor step 2)**: the fat string descriptor now exists as a real IR type -- `{ root, data, len }` under managed modes, `{ data, len }` under headerless -- with `__jac_str_wrap` (header-aware length) / `__jac_str_wrap_raw` (raw strlen, for foreign pointers) / `__jac_str_unwrap` (pass the data pointer through when it is already NUL-terminated at `len`, else materialize a NUL-terminated copy via `__jac_str_new`). Every `str` crossing of the clib membrane -- classified-ABI calls and plain foreign externs, arguments and returns -- routes through wrap/unwrap while core ops still traffic in `i8*`, so the membrane plumbing is proven green before the core flip. Pinned by `test_str_descriptor_membrane.jac`; behavior byte-identical across gc modes.
- **Feature: atomic-RC crossing -- parallel `flow for` under `--gc rc`**: the emitted retain/release helpers now consume the atomic RMW's returned old count instead of a stale plain load, so racing releases can neither double-free nor leak -- this also fixes the latent race in the existing helpers at zero added single-thread cost (the RMW was already emitted on every retain/release; the fix uses its result). With refcounts genuinely atomic, `flow for` fans out over pthreads in `--gc rc` builds exactly as in enforced zero-RC builds, measured ~7x on 8 threads with all tasks hammering one shared string's header; output is byte-identical across thread widths and against the sequential build. `--gc cycles` keeps the sequential lowering (the cycle collector's global roots and color state are unsynchronized), as do Python and wasm; rc-debug builds also stay sequential.
- **Feature: per-child bump-pointer page sharing**: partitioned children now draw default-size pages from their parent instead of malloc'ing fresh chunks -- on a free-list miss the child carves a run of 4 pages, keeps one, and donates the rest to the parent's free list, cutting page mallocs 4x by construction and giving sibling allocations run locality. Pages stay parent-owned: run-resident pages carry a marker bit so teardown frees whole runs exactly once (never interior pages), a dying child's runs and free pages splice to its parent alongside the existing chunk/dtor-log reabsorb, and the zombie-parent deferral is untouched -- the #7858 contract holds byte-identically across gc modes, pinned by a multi-page parent/children/grandchild stress fixture. Parent-side draw and splice are guarded by a per-region spinlock so children growing on parallel `flow` tasks stay safe.
- **Feature: zero-copy string slices (strings step 4)**: under managed modes a step-free string slice is now a view -- a descriptor whose data points into the parent at the computed offset with the parent's root retained -- with no per-slice allocation and O(1) construction; the copying path remains for stepped slices and for headerless builds until the derivation-subset rules land with C2. Views release through the same root-riding RC as every descriptor, materialize automatically at any consumer that needs a NUL-terminated whole (the bridge's probe-unwrap), and flow allocation-free through `len()`, truthiness, and descriptor-typed parameters. Measured 1.7x end-to-end on a 20M-substring extraction loop with identical digests; pinned by an IR gate (view construction present, no allocation in the slicing function) plus the three-mode behavioral identity and the full string oracle set.
- **Feature: view storability floor + derivation subset (item 2)**: in nogc-enforced modules a step-free string slice of a borrowable place (`own`, `&`, `&mut`, `imm`, or `self`) is now a checked zero-copy view: the binding is stamped a borrow of its base, so the existing borrow machinery enforces view-outlives-owner (E1304/E1301) and named-escape (E1306) for free, while the new `E1315` fences what borrows alone cannot see -- views smuggled into container grows or literals, stored into fields or module globals, bound `own`, or returned outside the elision subset. The elision subset is the promised derives-from dataflow: a function may return a view derived from its single `&`/`imm` parameter (a method from `self`), two-plus candidates reject, and call results of eliding functions are themselves stamped views of the licensed argument, so derivation chains check transitively. With the bound in place, the enforced headerless build now emits rootless `{data, len}` views for exactly the licensed shapes -- no retain, no allocation, `--assert-no-rc` clean -- pinned by a new IR gate cell, a three-fixture compile-fail corpus, and the `own_strops` oracle running view-bearing under all three modes plus erasure. Slicing also got representation-exact: descriptor receivers feed root/data/len straight from the descriptor (O(1) length, no probe-unwrap), which retires a latent unrooted-view hazard on chained tail slices in managed modes. Dict/set subscript keys stay storable (keys are hashed copies at the membrane); the copy idiom for escaping data is a stepped slice (`s[a:b:1]`).
- **Feature: zero-copy parse kernel + descriptor-native string ops (C6)**: string comparisons where either side is a descriptor now run length-aware `memcmp` over descriptor parts (`__jac_str_cmp3`: common-prefix memcmp, length tie-break, strcmp-sign semantics) and char subscripts on descriptor receivers read the data pointer directly into the static char cache -- neither materializes a NUL-terminated copy, closing the last per-token allocations on the view path. The new `own_parse` ownbench kernel is the acceptance witness: a tokenizer whose tokens are slice views of the borrowed source, classified by keyword compares, char probes, and length, with the enforced build's tokenize loop containing zero allocation calls (pinned by an IR gate alongside a view-present managed cell), byte-identical digests across the three gc modes and the Python backend, and `--assert-no-rc` held. Measured 1.4x end-to-end against the same kernel with copying slices at ~100M tokens (~63M tokens/sec enforced).
- **Feature: the fat-descriptor core flip (strings step 3)**: native `str` values at ABI positions -- locals, parameters, returns -- now carry the JacStr descriptor ({root, data, len} managed, {data, len} headerless) instead of a raw `i8*`. Memory at rest (container elements, struct fields, tuple slots, optionals) keeps `i8*` roots until C2 storability, with a single conversion bridge in the coerce layer (raw-wrap on the way in -- interior pointers must never be header-probed -- and NUL-probe unwrap on the way out); op dispatches normalize descriptor receivers, so every existing string path runs unchanged while `len()` and truthiness now read the descriptor's length field in O(1). The RC layer rides the descriptor's root; the clib membrane stays NUL-terminated `char*`; boxed hetero-list elements reconstruct descriptors through the same bridge; wasm keeps the legacy representation until a wasm descriptor ABI exists. The JIT marshal layer learns the scalarized ABI empirically pinned by the test battery: descriptor params flatten to (root, data, len) register args and descriptor returns read back as a two-pointer pair. Battery-green across the ownbench differential (all kernels, three modes, both erasure round-trips), the string gates, and the compile batteries; hand-rolled ctypes signatures in JIT tests migrate to a shared descriptor-aware helper.
- **Docs: wasm stays sequential; region-granular persistence design**: the wasm tutorial and concurrency references now state the permanent-for-now contract -- no wasm-threads story exists in the toolchain, so `flow for` and `flow` calls take their sequential lowering on the wasm triple with byte-identical output by the disjointness rules (documented behavior, not a bug). The region-granular persistence design pass (promoting a sealed region into the anchor store as a storage segment: hybrid segment-blob plus exploded graph-index representation, promote-on-seal / hydrate-as-inverse / mutation-as-explosion lifecycle, backend portability, and acceptance oracles) lands as an internals document ahead of any code, per its own design-first mandate.
- **Feature: by-value AoS element buffers + the recursive drop registry**: under enforced headerless codegen, `list[own T]` of a scalar-fielded archetype now stores elements inline and contiguous -- appends move the fresh payload into the buffer (one allocation per grow, none per element; the constructor shell is freed at move-in), reads yield interior pointers, index writes drop the old element in place first, and container teardown runs hooks-then-fields per element before one buffer free. Measured ~3x less CPU on a 4M-element build-and-scan against the pointer layout, digest-identical, and pinned leak-free by a macOS `leaks --atExit` gate (the deferred Valgrind-matrix stand-in). Managed modes keep pointer elements and the annotation erases, so output is byte-identical across gc modes; `own_aos` gains an AoS section plus its own erasure round-trip. The per-family element-drop stamps are replaced by a recursive `drop_fn_for` registry that resolves any element mangle (str, archetypes, nested lists/dicts/sets) to its teardown function instead of silently skipping unknown shapes.
- **Feature: owned module globals**: `glob x: own T` parses through the same ownership-prefix path as locals and parameters, stamps the symbol owned, and lifts the enforced-mode E1406 rejection of heap-typed module globals -- process-lifetime state in the owned world, with the process end as the extent (no header, no teardown, `--assert-no-rc` clean). This is the owned-global surface the walker-engine zero-RC factoring builds on. Unannotated heap globals keep the fence.
- **Feature: general parallel `flow` calls**: `h = flow f(args)` on a direct call now spawns a real task in parallel-capable native builds (enforced zero-RC and atomic-rc), generalizing the `flow for` outlining machinery to arbitrary calls with a per-callsite heap future record `{tid, result, args}` -- args capture by value (pointer args retained for the task, released by it under managed modes), a failed spawn falls back inline, and `wait h` joins, yields the result, and frees the future. The parallel lowering licenses itself only when the handle's uses are exactly one `wait` in the same loop scope and the callee returns an i64/float/pointer; every other shape, plus cycles/wasm/rc-debug builds, keeps the sequential erasure -- so behavior is byte-identical across gc modes by construction. `flow`/`wait` expressions also gain a proper typing rule (the target's type), matching the erasure contract on every backend.
- **Feature: `partition(n)` sugar**: `(a, b) = r.partition(2)` unpacks an owned region into n owned child handles in one statement -- sugar for n per-child `partition()` calls riding the same reabsorb/zombie contract. The checker licenses exactly the shape (integer-literal count matching the unpack arity, plain-name targets, owned `Region` receiver), stamps each child as an independently affine owned handle (double consumption is E1301, opens and seals see them as owned handles), and rejects every other partition-with-arguments shape with the new `E1314`. Native codegen lowers the unpack to n `__jac_region_partition` calls with scope-exit drops per child; the Python backend returns a real tuple. Byte-identical drops across gc modes, pinned next to the per-child contract test.
- **Feature: `flow for` reduction idiom**: an outer `int` accumulator whose only body uses are `acc += expr`, `acc = min(acc, expr)`, or `acc = max(acc, expr)` (one operation per accumulator, `expr` never mentioning `acc`) is now licensed instead of E1308 -- the checker proves the shape and stamps the fact, and the parallel enforced-build lowering gives each task a private partial seeded with the operation's identity, combining partials with the accumulator's pre-loop value at the join. Integer `+`/`min`/`max` are associative and commutative, so output is byte-identical across gc modes and any `JAC_FLOW_THREADS` width, and erasure to the sequential backends is exact. Every other accumulator shape (plain `acc = acc + x`, float accumulators, mid-loop reads, mixed operations) keeps E1308.
