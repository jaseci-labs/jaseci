- **Fix: Deleting a node no longer strands its edges behind a per-edge permission gate**: `destroy()` on a node re-ran the write-access check for every incident edge, so on a shared graph a commons node that opts into open deletion (via `__jac_access__` or a grant) could be deleted by any identity while the connecting edge owned by another root silently survived, dangling at the dead node until traversal quarantined it. The node is now the authorization boundary: once its delete is authorized, incident edges are detached and deleted with it. A denied node delete is unchanged, still a no-op that surfaces a `PermissionDenied` diagnostic in the response envelope's warnings.
