- **Docs: `flow for` orders side effects against the join, not against each other**: The borrow reference now states that only post-join state is deterministic. A `print` raised from inside a parallel `flow for` body lands before the next region's output but has no order against the other elements of its own loop, so code that needs an ordered stream should write through the `&mut` lend and emit after the join. The native `flow for` runtime test was pinning an exact byte sequence of per-element prints and flaked at about 1.5% per run; it now checks the same lines in the same regions in region order.
