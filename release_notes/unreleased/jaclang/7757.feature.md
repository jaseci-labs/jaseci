- **Compiler: whole-program placement solver (clean break)**: Codespace placement is now a whole-program, summary-based analysis. Each module gets a placement summary (per-element capability evidence, reference and escape edges, anchors), serialized into the `.jir` next to the bytecode; a single solver consumes summaries to make every placement decision -- the parse-time native verdict, per-module seeding and fixpoint, and the cross-module client pull, which now runs before codegen so `jac check` sees the same placements as `jac build`. The legacy seed/pull producer stack (`_seed_module_codespace`, `CodespacePullPass`, the ES-codegen pull hook, the nadefault closure scan) is deleted in the same change; `cl`/`sv`/`na` markers remain explicit overrides.
- **Explainability: `jac check --placements`**: Prints every top-level element's space (server / client / native, dual marked) with the evidence chain behind each decision ("seeded client: jsx construction", "dual client: pulled through plain import from app.jac"), plus an estimated boundary-crossing count. LSP hover shows `placement: <space> (inferred|explicit marker)` for any symbol.
- **Placement report**: `jac check --placements` prints every element's decided space with the evidence chain behind each decision (the "helper gained a python import and went server" class is now visible on demand).
- **New diagnostics and backstops**: W6006 warns when a mutable glob would be dual-emitted into both spaces (state fork); W6007 warns when client code uses a server-placed function as a value (0-CFA escape check generalizing W6005). Client-pulled elements that fail ES lowering demote back to the server with a note naming the cause, mirroring the native demotion contract. A portability fact base (`jac0core/portability.jac`, honestly empty today) governs which python modules may follow their referents client-side.
