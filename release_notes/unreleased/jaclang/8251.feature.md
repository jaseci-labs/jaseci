- **Native: jac decodes its own string literals, so `lit_value` lowers**: `String.lit_value` used to hand prefixed literals to CPython `eval` with an `isinstance(str_field, bytes)` narrowing, which made literal decoding a Python-only seam and shipped `String.lit_value` / `MultiString.lit_value` as abort stubs in `unitree`'s native artifact. `unitree.decode_string_literal` replaces it with one implementation both lanes run: quote-form and `r`/`b` prefix parsing, CPython's `str` escape set, and a separate byte-wise path for `b`/`rb`/`br` literals that masks octal escapes and refuses non-ASCII source the way CPython does. Malformed `\x` / `\u` / `\U` escapes now refuse instead of surviving as literal text, matching CPython; `\N{name}` refuses out loud, because resolving a character name needs the Unicode name database and every other `\N` spelling is a CPython `SyntaxError` anyway. `tests/compiler/test_literal_decoding.jac` generates its corpus from the lexer and the parser rather than listing one, then differential-tests 12818 generated plus 4033 harvested literal forms against `eval`. Both seam waivers are gone from the unitree census tables.
