- **Client codegen matches Python semantics for enums, dicts, and numeric parsing**: Bare enum members lowered to `null` in the ES backend (every member compared equal, so the same program behaved differently per codespace); they now number exactly as Python's `enum.auto()` does, and boundary enum stubs carry the same values (member collection previously produced empty objects because it read `Assignment.target` as a single node). `dict(d)` no longer throws on the common copy shape (dicts are plain objects, not pair-iterables); `for k in d`, `list(d)`, `sorted(d)`, and `enumerate(d)` iterate keys as Python does via type-directed lowering with a runtime dispatch fallback for dynamically typed values; `float()`/`int()` are strict parsers that raise `ValueError`/`TypeError` where CPython does instead of `parseFloat`-style partial parses that silently produced `NaN`. Absolute local imports in nested modules now emit importer-relative specifiers instead of root-anchored paths that only resolved from the project root.
- **Toolchain fixes from dogfooding a full-scale client app**: the shadcn registry pins version ranges for every component npm dependency (unbounded `*` ranges installed whatever major was current and broke vendored components, e.g. react-resizable-panels v4's renamed exports vs the v2 API the component targets) and component lookup accepts underscore spellings (`scroll_area`); editing `[dependencies.npm]` re-syncs node_modules via a manifest-hash marker (installs previously never re-ran once node_modules existed); bun resolution falls back to PATH and `~/.bun` on source checkouts; bare `jac create` only refuses at an existing project root rather than anywhere under an ancestor project; W2075 no longer misfires on `v is True` identity tests over non-bool operands.
