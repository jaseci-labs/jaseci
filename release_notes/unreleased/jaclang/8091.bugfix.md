- **Native: an optional payload inside a returned tuple segfaulted at the read, or refused to compile**: a tuple slot declared `T | None` is a JacOpt (presence tag plus payload) in the boxed tuple's layout, but the constructor boxed the value tuple with the layout its elements arrived in -- the bare payload pointer -- and bitcast the box to the declared type. Every later read decoded the declared layout against that memory: the payload pointer's low byte became the presence tag and the neighbouring slot became the payload, so a present payload was a garbage pointer by the time `__rc_retain` touched it (the repro faults at `0x1 - 16`, the bool slot read back as a pointer), and the box's destructor released slot 0 as a plain pointer besides. The same shear had a compile-time face: a value tuple that already carried a JacOpt element (`return (x, Box(...))` with `x: Box | None`) matched no boxing rule at all, so the raw value struct reached `ret` and failed LLVM verification. `_coerce_type_inner` now runs a value tuple through `_coerce_tuple_to_struct` against the declared pointee before boxing, so the box, its destructor, its trace fn, and every slot read agree on what each slot holds; element coercion is the existing JacOpt machinery, so a null payload wraps to the None form and ownership flags ride through unchanged. This is the sealed parser's `parse_from_path -> from_loc` shape: `import from x { y }` aborted the sealed parser before and parses at full node-count parity now.
