- **CLI: `jac seal`, and a seal that says what it is doing while it does it**: The native seal gate gets one front door. `jac seal <mod.jac>` seals any module as its own unit and `jac seal --compiler` seals the running tree's served compiler surface, both reroute-native (under `[dev] jaclang_source` no binary rebuild is needed) and scratch-safe by default, with `--ir` for the unit's LLVM text and `--debug` for the reason behind every demotion; a refusal exits 1 with the gate's diagnostics and leaves no artifact behind. That front door narrates itself: a seal is a long pipeline whose every refusal names a phase, so each phase (`stage`, `compile`, `gate`, `layout`, `link`, `canary`, `write`) now announces itself when it opens and closes with its result and what it cost, the purge-and-recompile retry that used to look like a hang is visible as a retry, a refusal marks the phase that refused before the gate's diagnostic, and the run ends on an artifact/layout/triple block. `jac build --as sealed` inherits the same reporting. The native backend's user-facing warnings -- the seam demotions and field erasures, the struct-name collision, the linker's unresolved references and unhandled DWARF relocations -- move off raw `sys.stderr` onto the console, so they arrive as real warnings with the rest of the CLI's vocabulary rather than as bare text; the `NA_DEBUG`/`SPECMISS` traces stay raw, since they are grep-anchored developer output.
