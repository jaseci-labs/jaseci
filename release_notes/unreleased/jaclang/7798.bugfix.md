- **Fix: byLLM honors a configured `api_base` again**: A custom endpoint set via `Model(config={"base_url": ...})` (or `host`/`api_base`, or `[byllm.model] base_url` in `jac.toml`) was resolved into the request params and then popped straight back off into `self.api_base` — an attribute only the `proxy` and `http_client` branches read. On the default LiteLLM path the value was silently discarded, so requests went to the provider's own endpoint (`api.openai.com` for `gpt-*`) instead of the configured gateway. The resolved value is now passed to all four `litellm.completion`/`acompletion` call sites; `api_base` is a declared field on `BaseLLM` rather than an attribute attached at dispatch, and joins the resolution chain so a constructor-supplied value survives. `ModelPool` was unaffected — it already wired `api_base` into the LiteLLM `Router`.
