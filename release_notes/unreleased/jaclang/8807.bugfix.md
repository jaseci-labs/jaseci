- **Intel Macs: a release can now ship without an Intel binary**: The macOS x86_64 build has been unreliable, and one broken platform no longer holds the whole release back for everyone else. If a release has no Intel Mac binary, there is nothing to install in its place: the macOS binary that did build is arm64 (Apple Silicon) code, and Rosetta translates x86_64 onto Apple Silicon rather than the other way round, so it cannot run on Intel hardware. The installer now says this outright, names the most recent release that does carry an Intel build, and prints the exact command to install it. Stay on that release until an Intel build ships again. Apple Silicon Macs, Linux x86_64 and Linux aarch64 are unaffected and install as usual.
- **Fix: the installer says what is wrong instead of guessing**: When a release had no binary for your platform, `install.sh` failed on the download with a list of possible causes ("the version does not exist", "a native binary is not available", "network issue"). It now checks the release's own asset list before downloading, so a genuinely missing platform gets an explanation and a way forward, and a real download failure is reported as the network problem it is.
