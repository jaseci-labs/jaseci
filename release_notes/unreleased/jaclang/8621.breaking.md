- **Fixed-width numerics are erased to the machine representation on the server and client lanes** (#8532): `i8 u8 i16 u16 i32 u32 i64 u64 f32 f64` no longer allocate a wrapper object per value. The checker records the sized type of every expression once (`Expr.fw`) and each backend emits the range check the trapping contract needs, so a sized value is a plain `int`/`float` on the server lane, a JS number (or `BigInt` at 64 bits) on the client, and its own machine width natively. The semantics are unchanged and pinned by the cross-lane conformance fixture, which now covers all ten types and fails if a lane drops a row. Augmented assignment (`w += 1`, `c.field += 1`, `lst[0] += 1`) is range-checked on the server lane, which it was not before. **Breaking:** the ten runtime classes are gone, so `type(x) is i8`, `isinstance(x, u8)` and `x.__jac_sized__` no longer work, and `wrapping_add`/`wrapping_sub`/`wrapping_mul`/`wrapping_shl`/`wrapping_neg` must be called directly rather than taken as values. `T(x)`, `T.wrap(x)`, `T.MIN` and `T.MAX` are unchanged. Measured on a 300k-iteration `i32` loop the server lane goes from 460x to 3.0x plain-`int` cost and `f32` from 165x to 4.0x; a 3M-iteration `i32` loop on the client lane goes from 36.9x to 1.6x.
