- **Fix: a crash-looping pod the deploy never touched no longer fails a healthy rollout**: the rollout scanner judged every pod in the namespace, so a namespace holding any crash-looping stranger - most commonly an orphaned pre-rename Deployment of the same app, which the rename reaper cannot match by selector - failed every deploy into it with `fleet did not become ready`, no matter how healthy the deployed fleet was. The crash-loop branch now fires only for pods the deploy owns: the fleet's own Deployments (the guard its ImagePull and stuck-ContainerCreating siblings already had) plus the companions the deploy provisions beside them (`{app}-redis`, `{app}-mongodb`), whose crash loops still fail the rollout. With no fleet names known, every pod still counts.
