- **Fix: native dicts keyed by an int-valued enum**: a native dict lowers an enum key to the enum's native integer, which is the member ordinal for a string-valued enum but the declared value for an int-valued one. Reading a key back out ignored that distinction: `.name`/`.value` on a runtime enum-typed value indexed the per-enum ordinal arrays with the raw key, so an int-valued enum named the wrong member or read past the end of the array, and `.value` had no array to index and lost the module to E5092. `.name` now maps the value back to an ordinal through a per-enum resolver and `.value` returns the value directly, so `dict[<int-valued enum>, V]` can be iterated and its keys inspected. Enum keys stay integers: hashing and equality are unchanged.
