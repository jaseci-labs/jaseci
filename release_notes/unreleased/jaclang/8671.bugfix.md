- **Fix: type variables no longer escape into diagnostics as a bare `_T`**: Two independent gaps let an unsolved type variable reach the author. A protocol is satisfied by shape, so the nominal walk to it found no path and handed the protocol's own declared parameters straight back, and the caller then bound `_T` to `_T`, so `next()`, `iter()` and every other `SupportsX`-typed signature returned an unusable `_T`. The protocol's methods are now unified against the ones implementing them, with the implementing side specialized so `Iterator[int].__next__` reads as `-> int`. Separately, specializing an unparameterized generic for a base class kept the class's own parameter instead of the `list[any]` that W1036 already states is the rule, so `enumerate(xs)` over a bare `xs: list` leaked it too.
- **Fix: `Object.is` and `Array.from` resolve**: A stub written in Python syntax cannot declare a member whose name is a Python keyword, so the ambient JS globals spell these `is_` and `from_`. Nothing honoured that, and reaching them the only way Jac can (``Object.`is``) reported "has no attribute".
- **Fix: `Self` binds correctly through a class object**: `Base.__subclasses__()` read as `list[Base]` rather than `list[type[Base]]`, and a member reached through a `type[X]`-typed receiver bound `Self` to `type[X]`, so `cls.__new__(cls)` appeared to build another `type[X]` instead of an `X`. The class's own MRO is consulted first, so a name the class declares itself still takes the instance reading.
- **Refactor: `.jacignore` drops from 428 entries to 37**: 45 entries matched no file at all and 308 covered modules that already pass `jac check`. Every surviving entry is path-qualified one module per line, because matching is `fnmatch` against every path component, so the previous bare basenames silenced every file of that name repo-wide. `FunctionType.parameters` is also declared as the list `postinit` has always made it, rather than `list[Parameter] | None`.
