- **Fix: ACL writes are gated at the call, and the commons floor is policy instead of a grant the first toucher writes**: a static scheduled task touching `root.shared` as the internal `__system__` user logged `Permission denied: field_write on Root[...] required WRITE, have CONNECT` once per flush for the whole tick. `get_shared_root()` wrote a CONNECT grant onto the guest root from whichever session touched it first, the flush-time backstop refused that row under the toucher's principal on every later flush, and the scheduler and HTTP middleware reset the request context before closing the session, so the close-time commit ran as the super root and persisted the refused row anyway (the deferral of #8346 on the ACL path #8656 left ungated). `allow_root`, `disallow_root`, `allow_group`, `disallow_group`, `perm_grant` and `perm_revoke` now check write access at the call under the acting principal (operation `acl_write`), the same shape as field writes, edge writes and delete, so a denied ACL write leaves nothing for any later flush to pick up and strict mode raises. The shared root's CONNECT floor lives in `check_access_level`: a never-granted commons reads as CONNECT for every principal, an explicit level is respected, per-root and group entries still apply, and nobody writes a grant to make it usable. Root-typed hops resolve through the runtime rather than the store's ACL pushdown, and sessions close under the request principal.
