- **OSP centralization completed: the tail of one-engine-across-backends is deleted, enforced, and closed (#7963, closes #7941)**: The server store now participates in the region mechanism -- every per-context driver store tags its rows with a region id, and `TieredMemory.close` retracts them via `osp_region_died` while recycling handle-table slots that previously pinned anchors for the life of the process, so long-running servers are bounded by live topology. `NodeAnchor.edges` is retired as a live read path: hydration (including batch stub fetch) lives inside the driver, `EdgeAnchor.detach` retracts from the store itself, liveness is evidence-based (`sv_edge_alive`), and the planner's `[edge -->]` arm, graph-view walks, and byLLM edge inference all enumerate through `sv_live_edges` -- a purity-contract scan pins the remaining persistence/OCC readers to an exact sanctioned table, and a persist/reload round-trip gate pins the dynamic half. Access control moved into the traversal seam: `_hop_once` and the edge arm filter everything they surface through `check_access_level` for downscoped users, so bare edge refs, planner queries, and walker visits over the same graph produce one transcript and a future read path cannot bypass the ACL by construction (single-tenant flows keep the ungated lazy hop path). The sv kernel adapter's duplicate sequential tag registry is deleted -- dispatch and store rows share the one stable content-hash tag space na and cl compile against. Nested-walk report bubbling moved from the sv host into the portable kernel (`WalkScope.nested`), pinned cross-backend by a new `osp_nested_report` equivalence gate, and the one-substrate interop fixture now runs with `require=["na", "cl"]` -- native executes mid-walk graph growth inside walker abilities identically to the reference. Note: graph views truncated by `node_limit`/`edge_limit` now enumerate edges in the store's canonical adjacency order (out-chain then in-chain), the same order every backend produces.
- **Kernel compilation units are stable, content-keyed artifacts**: the OSP core (osp_kernel + osp_graph) and fmt kernel were copy-compiled from a fresh tempdir by every consumer in every process -- the client JS builder, the native symtab loader, and both native IR compiles -- so nothing could cache and native debug metadata embedded ephemeral paths. All five sites now consume `jac0core/kernel_units`: units materialize once per (name, content) at stable paths under the jac cache root, and derived kernel JS/LLVM IR persist beside them keyed by the materialized unit plus the consumer's emitter fingerprint, so staleness is impossible by construction and warm builds read artifacts instead of recompiling.
