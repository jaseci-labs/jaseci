- **Feature: GraphMend graph-break elimination (on by default for torch code)**: GraphMend eliminates PyTorch 2 FX graph breaks at compile time and is on by default in `auto` mode: it engages per compiled module exactly for modules that import `torch` or a `torch.*` submodule, detected syntactically at compile time (torch need not be installed), so every other module compiles byte-identically to before. TorchDynamo falls back to eager execution whenever traced code forces a Python-level decision on tensor data, and each such break splits the compiled region. GraphMend detects the fixable break patterns under `torch.compile` entry points (decorated functions and classes, or call-site wraps like `torch.compile(Model())`, resolved through the symbol table) and rewrites them so the forward pass stays a single contiguous FX graph. Data-dependent validation guards lower to graph-native `torch._assert_async`, with the original exception type and message folded into a compile-time marker and restored by an eager boundary decorator. Data-dependent `if`/`else` branches are predicated into `torch.where` selections; multi-statement branches hoist their setup only when each statement is provably effect-neutral on the untaken path. Side-effecting calls are deferred: `print` calls buffer and replay in program order after the graph runs, and logger calls go through an integer slot registry flushed by a forward hook, since TorchDynamo cannot trace a `Logger` method at all; an eager boundary guard drains the buffer even on exceptional exits. A `--graphmend-scope` flag extends the transforms to imported `.py` model code (for example Hugging Face modules) by claiming scoped modules in the import system and compiling them whole-module; a scope alone forces GraphMend on for the run. The passes run immediately before Python code generation and self-gate on the resolved per-module mode, and GraphMend-active compiles participate in the bytecode cache with the GraphMend configuration folded into the cache key, so repeat compiles hit the cache, GraphMend-on and GraphMend-off artifacts never collide, and flipping any GraphMend option invalidates correctly. Detection matches structurally rather than against unparsed text, so it works on plain `.py` model source (`jac run model.py`) as well as `.jac`.
- **Feature: GraphMend configuration through jac.toml**: The mode is the tri-state `[run] graphmend = "auto" | "on" | "off"` key in `jac.toml` (default `auto`; booleans stay valid), mirrored by `CompileOptions(graphmend=...)` for embedders; there is no CLI enable flag. `"off"` disables GraphMend entirely, and `"on"` forces it for every compiled module.
- **Feature: Per-transform GraphMend toggles**: Each GraphMend transform (trap, where, defer) can be disabled individually via `jac run --graphmend-disable`, the `[run]` section of `jac.toml` (`graphmend_scope`, `graphmend_disable`), or `CompileOptions(graphmend_disable=[...])`, with explicit CLI flags taking precedence over `jac.toml`.
