- **Fix: the sealed native parser no longer leaks its parse tree** (#8146): every parse through the sealed native parser permanently stranded its whole parse product, proportional to node count, so a long-lived process that parses repeatedly grew without bound. Three causes had to be fixed together, because each one alone leaves the others holding the tree and so measures as no improvement at all. Returning a borrowed element retains it to give the caller ownership, and a method call frees that receiver afterwards, but a field read only indexes into it, so `self.current().kind` left every token's refcount one higher on every inspection. The tree is also cyclic three ways (parent links, a token's location record naming the token itself, and a name node's `name_of` pointing at itself), which refcounting cannot reclaim, so the materializer crossing now dismantles it at the one point where it is provably dead: `mat_parse` has already copied it into CPython objects and `mat_parse_diags` never hands it out. Two of those links live on non-optional fields with no value meaning "no node", so they are repointed at a pin rather than nulled. Ten parses of a 49 KB source now strand 0.950 MB instead of 15.637 MB. This covers the parse and diagnostics crossings, which is what a language server and the parity paths use; `mat_parse_and_run_prefix`, which a full compile goes through, merges annexed modules and runs the prefix passes, so it cannot use this teardown and still leaks.
