- **Fix: a retiring worker could kill the worker that replaced it**: `WorkPool` never dropped a retired worker from its kid list, and the forked child closes every sibling's pipe file descriptors by number. Once a reaped worker's descriptor numbers were recycled by a later `os.pipe()`, a newly spawned child could close a live pipe, including its own dispatch end, and exit at once; the parent then reported `worker exited while running this item` for the item it had just handed over, and that item was lost. The same accumulation leaked two descriptors per retirement until shutdown, which `select()` cannot survive past descriptor 1024. Neither shows up until enough retirements pile up, so short pool runs never caught it, but retirement fires on the resident-memory ceiling in the precompile and check lanes, so any workload that pushes workers over that cap was exposed. Retiring after every item now completes all 400 items in the new regression test, where it previously failed 390 of them.
- **Fix: compiling the same source twice could produce different bytecode**: a `comptime` set was lowered into the emitted literal by iterating it, and Python randomizes string hashes per process, so the constant carried whichever element order that particular compiler process happened to have. Two compiles of one unchanged module produced different bytecode and therefore different `.jir` bytes, which defeats build reproducibility and the content addressing the seeded JIR cache depends on. Comptime set elements are now emitted in a deterministic order. The `ct_mangle` fallback took the same randomized hash of a `repr` and now takes a sha256 prefix instead; it names generic instantiations, so it had the identical defect.
