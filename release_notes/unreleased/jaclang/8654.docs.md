- **`scale/TESTING.md`: the protocol for validating a jac-scale change**: Scale failures only appear when real processes talk to each other, so a green unit run says almost nothing about them. The new document states the rig that makes a result trustworthy (build the branch with `zig build -Ddev`, prove the binary is serving your source rather than its baked jaclang, re-pin capability deps after every rebuild), the kind of test a scale change earns (trophy weighting, no mocks, a regression test that fails pre-fix), and the ladder before a pull request (static, targeted suites per CI group, the real command as a subprocess, a real deploy) with the axes that routinely disagree and the cluster discipline that keeps a shared box usable. Commands are current as of the `jac start` retirement and include the migration table.
