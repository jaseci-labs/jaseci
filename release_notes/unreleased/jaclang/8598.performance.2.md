- **Traversal results realise lazily, so the query answers what was asked**: `[a --> [?:T]]` returned a fully materialised list, so `len(...)`, a truthiness test and `[:n]` each read the whole neighbourhood regardless of how little of the answer was wanted. The result is now a lazy list: `len()` becomes `SELECT count(...)` and deserialises nothing, a truthiness test stops at the first row, and a simple forward slice becomes `LIMIT`/`OFFSET`. Any other list operation realises first and behaves exactly as before -- the value is still a `list`, still compares equal to one, and `jac check` still types it `list[T]`. A bound is pushed only when the request is not ACL-gated, so `[:n]` keeps meaning "n rows you may see".
