- **Native codegen diagnoses unresolvable signature annotations instead of silently laying them out as i64**: `NaIRGenTypes._resolve_jac_type` had a bare `return ir.IntType(64)` fallthrough for a non-None annotation node whose semantic type was never stamped. Every caller of this helper is a type-annotation / signature position (params, returns, object fields, var/set decls), so a genuinely-unresolved annotation silently became i64 storage/ABI with no diagnostic, bypassing the pass's own `_emit_unlowerable_type` backstop (E5092). That fallthrough now routes through `_emit_unlowerable_type`, so an unresolvable annotation fails loudly and the native artifact is withheld. The `type_expr is None` path is intentionally unchanged: an absent annotation (e.g. an ability with no `-> T`) is a legitimate default, not an unresolved type.
