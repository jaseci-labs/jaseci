- **Native: a direct field store through a mixin-typed reference is pinned by value, and its workaround is gone** (issue #8086): field slots are numbered in MRO order, so a mixin's field lands at a different index in every class that reaches it through a different linearization. While a store compiled at the static base's single index wrote a *neighbouring* field on any class that disagreed, `ContextAwareNode.set_code_context` existed purely so the parser's one polymorphic write (`stmt.code_context = CodeContext.NATIVE` over the element statements of a `clib` import block) could route through a dispatched setter on the owning mixin instead. The defect itself was fixed shortly afterwards -- a field access whose static receiver class places the field at class-varying slots now emits an identity-dispatched gep at each concrete class's own index, on the store side as well as the read side -- which left the setter as dead weight the call site still had to know about. The capability is now covered directly rather than implied: a new fixture puts `code` at slot 2, 5 and 6 across three classes that mix in the same base, and every store route through a base-typed reference (a plain local, a base-typed parameter, a `list[Ctx]` element, an augmented assign) is read back by value through the *concrete* class -- the stored value itself, plus the sum of every other field, a per-class constant that only moves when a store strays -- and compared against the sv/bytecode result of the same fixture. The dispatched setter runs beside the direct store in the same fixture, so the two routes are checked against each other rather than one standing in for the other. With the guard in place `set_code_context` is deleted and the call site is a plain field assignment again; the native parser's seam census is unchanged.
