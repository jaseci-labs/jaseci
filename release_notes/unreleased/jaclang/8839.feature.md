- **The JIR cache now carries analysis, not just artifacts**: every compiled module persists its exported interface (typed symbols, signatures, archetype layouts, access/ownership facts), its direct dependencies with the interface hash each had at compile time, and the diagnostics the compile delivered. A warm no-edit `jac check` replays those diagnostics without running a single compiler pass (the chess fixture's per-check analysis work drops from ~570ms to ~1ms), dependency ingestion hydrates cache-valid imports from their interfaces instead of re-running their frontend, and a body-only edit to a dependency no longer re-analyzes its importers because its interface hash does not change. There is no switch to turn hydration off: `JAC_REBUILD=1` recomputes and rewrites the cache with identical results, and `JAC_IFACE_VERIFY=1` (run in CI on the equivalence suites) recomputes everything served from cache and fails on any divergence, so a warm cache can never change what the compiler reports or generates. Cold language-server starts also get their who-imports-what fan-out from the persisted dependency edges, and the compiler's own startup no longer sha256-sweeps its source tree once a stat manifest is warm.
