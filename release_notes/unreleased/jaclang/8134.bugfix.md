- **Fix: `AuthGuard` renders its children instead of blanking the page**: on the React and react-native backends `AuthGuard` accepted only `redirect` and returned `<Outlet />` for every authenticated visitor. `Outlet` renders the *matched child route*, so the documented wrapper form `<Route path="/dashboard" element={<AuthGuard redirect="/login"><Dashboard /></AuthGuard>} />` had nothing to resolve and rendered an empty slot -- a blank protected page with no compile error, no console error and no warning, since React treats "no matched child" and "component returned null" as normal. Solid's implementation already read `children`, so one `@jac/runtime` export had two contracts. Both React implementations now take `children` and keep `<Outlet />` as the fallback, which leaves every existing call site unchanged: the `(auth)/` codegen and `<Route element={<AuthGuard />}>` pass no children and still resolve their child routes, and the documented `<AuthGuard><Outlet /></AuthGuard>` layout now renders the user's own `<Outlet />` -- the same component it was already rendering. The generated React entry also goes back to building the guard with props (`React.createElement(AuthGuard, { redirect })`) rather than calling it with a positional string, which destructured to the `/login` default and discarded `[client.routing] auth_redirect` for every user. React and react-native gain the jsdom `AuthGuard` coverage they never had -- the guard's four call shapes in both auth states, plus the generated file-based entry -- which is what let both defects ship: a logged-out redirect assertion passes on the broken code, so the logged-in render is the assertion that catches them.
