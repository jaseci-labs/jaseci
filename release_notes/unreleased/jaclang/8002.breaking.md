- **Breaking: Mongo/Redis/Firestore/SQLAlchemy scaffolding removed**: The remaining affordances from the pre-0.36 storage stack are gone. `[eject.db]` legacy drivers (`sqlite`/`sql`/`sqlalchemy`) now fail at eject time with a diagnostic (the runtime persists natively to Postgres; set `JAC_DB_URL` or rely on the embedded server). `[scale.websocket].backplane` accepts `memory` or `pg` only. The sqlite identity fallback is removed: serving without a reachable database fails loudly instead of silently opening a second credential store. The `data.mongo`/`data.redis`/`data.sql` capabilities and their intent rules are removed, so served apps no longer close over `pymongo`/`sqlalchemy`.
- **Fix: scheduler and ops defects from the clean break**: `/jobs` endpoints return 503 `STORAGE_UNAVAILABLE` on Postgres outages (the branch previously tested the unraisable `PyMongoError` and always fell through to 500), the admin ops page renders the Postgres health card (it iterated a stale mongo/redis signal list), webhook API-key lookups are indexed, and every `[scale.*]` section read by the config loader is schema-declared.
- **Breaking: pre-0.36 (bcrypt) password hashes cannot verify; operators get a signal and a reset flow**: Credentials written before the scrypt migration fail as generic invalid-credentials to the client (no oracle), but the server now logs one rate-limited WARNING per credential naming the cause. Operators can run `POST /admin/users/expire-legacy-credentials` (bulk, or with `username` for one account) to flag every pre-scrypt account with `requires_password_reset`, then drive resets through the existing admin reset flow. Separately, the password-hash cost knob is no longer a memory-DoS vector: effective scrypt `n` is capped at 2^15 (~32 MB per attempt), `hashlib.scrypt` gets an explicit `maxmem`, and `password_hash_cost` / `JAC_SCALE_PASSWORD_HASH_COST` clamp to 10..15. A hash stored under a misconfigured cost 16-17 refuses to verify (with a WARNING) and needs the same reset flow.
- **Fix: multi-pod scheduler and WebSocket backplane correctness**: Each due job now fires on exactly one pod (a per-fire Postgres lease; no leader election), and `POST/PUT/DELETE /jobs` propagate to every pod over `LISTEN/NOTIFY` so a deleted job stops firing everywhere without restarts. The WebSocket backplane no longer double-delivers broadcasts on the publishing pod, oversized (>7000 byte) broadcasts published from inside an open transaction are delivered (the spill row rides an autocommit side connection), and cross-pod fan-out is push (select on the LISTEN socket) instead of a 1 Hz poll. `[scale.events].url` validates its scheme at boot with a clean error.
- **Breaking: serving hardening (restspec, trailing slash, WebSockets)**: `@restspec` misuse now fails at boot instead of registering dead or silently-altered routes: junk `method`/`protocol` values raise (strings like `'get'`/`'ws'` coerce), `method=HEAD` is rejected, webhooks are walker-only, `broadcast` requires WEBSOCKET, and ignored knob combinations warn. A `@restspec(path=...)` def without `method=` serves at POST instead of 404ing on every verb. Trailing-slash misses 307-redirect to the canonical route again. WebSocket upgrades honor the drain grace period, answer PINGs interleaved in fragmented messages, enforce `max_message_bytes` during reassembly (close `1009`) before auth, and deliver real close codes pre-accept. **Cross-origin WebSocket upgrades are refused by default**: set `[scale.websocket] allowed_origins = ["https://app.example.com"]` (or `["*"]`) if your WS clients are served from a different origin. OpenAPI documents now carry response content types, real auth requirements for custom-path endpoints, and WebSocket routes.
