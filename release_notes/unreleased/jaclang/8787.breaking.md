- **Breaking: client build failures report `E7xxx` codes at a Jac location, and the `JAC_CLIENT_00x` codes are gone**: A failed client bundle build at server startup was the last path served by a separate regex detector battery, which printed boxed `JAC_CLIENT_001` / `JAC_CLIENT_003` / `JAC_CLIENT_004` diagnostics. It now runs through the same classifier the dev loop uses and renders with the same renderer as `jac check`, so each error carries an `E7xxx` code, the `.jac` line the compiled artifact was lowered from (or a note saying why one could not be derived), and the registry's help text (including W1106's `[dependencies.npm]` guidance for an undeclared package). Scripts matching on `JAC_CLIENT_00x` must match on the `E7xxx` codes instead; run `jac guide reference/diagnostics` for the catalog. `JAC_DEBUG=1` (or `[client] debug = true`) still appends the raw bundler output.
- **Breaking: the `format_build_error` plugin hook is removed**: `Jac.format_build_error(error_output, project_dir, config)` existed only to let a plugin re-format client bundle build failures, and its one implementation was the detector battery. Client error classification is now a single engine in `jaclang.client.client_diagnostics`; a plugin that overrode the hook should extend `classify_build_output` instead.
