- **A native-backend or runtime edit no longer rebuilds the module cache world**: under the old whole-tree digest, one edited byte anywhere in the compiler source flipped every cached module's key and the cache refilled lazily, one serial miss at a time (77-216s per entry point on a large working set). With producer-cone keys, an edit under `compiler/backends/native` recompiles one module in about a second, with every other cached bytecode artifact measured byte-identical (643/643 in the validation run); runtime and stdlib edits invalidate nothing but themselves. Jirs that carry native sections are stamped with a `SEC_NATIVEKEY` checked before restore, so a native-compiler change drops exactly the stale native objects while the bytecode beside them stays warm.
- **Dev-mode generation reseal**: when the codegen cone does change, the dev CLI (`JAC_DEV_SOURCE` set) now batch-rebuilds the recently-warm working set at dispatch across forked workers instead of refilling the cache lazily: recent generation directories record which modules the machine had warm, those map back to their sources, and each compiles through the same persist path a lazy miss takes (39-72s parallel versus the serial refill, and every entry point is warm afterward). The new `JacCompiler.unit_retain` flag keeps analyzed closures across units so workers stop re-analyzing shared deps. Correctness never depends on the pass: anything skipped or failed recompiles lazily as before, and `JAC_DEV_RESEAL=0` disables it.
- **`scripts/jir_generation_diff.py` audits cache invalidation**: it diffs the bytecode sections of two cache generations and reports the spurious-invalidation rate, making cone boundaries empirically checkable. Its first run surfaced nondeterministic bytecode in `cli/commands/mcp.jac` (identical source, differing bytes across compiles), tracked as a follow-up.
