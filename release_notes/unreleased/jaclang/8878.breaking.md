- **The client runtime is React 19: `ref` now reaches your components**: `react`, `react-dom`, `@types/react` and `@types/react-dom` move from `^18.2.0` to `^19.2.0`, so a compiled `def:pub` component receives `ref` as an ordinary prop instead of having React strip it. That fixes the silent failure where a Radix primitive used with `asChild` around a Jac component got no positioning anchor (`Function components cannot be given refs`) and its popper landed at the viewport origin -- a `DropdownMenuTrigger`/`TooltipTrigger` wrapping a Jac `Button` now anchors correctly, and the jaclang.org Socialize sidebar and TweetCard use that natural pattern again. The rule: `ref` is a prop and you place it. A `props: any` bundle component already receives it as `props["ref"]`, and any `{**props}` spread onto a host tag forwards it (this is what every jac-shadcn primitive does); a named-param component still declares a trailing `ref: Ref[T]` parameter, which keeps lowering to `forwardRef`. The compiler does not thread `ref` onto an element for you. What you may need to change: an existing project's `jac.toml` keeps whatever `react` version it pinned by hand, so bump it there to pick this up (projects that never pinned react self-heal to the new set on the next `jac install`); the four internal copies of the react pin collapsed into `CORE_RUNTIME_DEPS`/`OPTIONAL_RUNTIME_DEPS`/`CORE_DEV_DEPS` in `npm_provider.jac`, which is now also where the published `@jac/runtime` peer deps come from.
