- **Scale: app-facing single-use tokens (`jaclang.scale.identity.app_tokens`)**: apps no longer need to hand-roll invitation tokens with a `used` flag whose read-then-write lets two concurrent accepts both win. `token_create(purpose, subject, ttl_seconds, payload)` mints a `secrets.token_urlsafe(32)` value shown once and persisted only as its sha256; `token_consume` redeems it for exactly one concurrent caller (atomic delete); `token_peek` inspects without consuming; `token_revoke(purpose, subject)` cancels outstanding tokens. Purposes are namespaced (`app:` prefix) so they cannot collide with the identity endpoints' internal `verify`/`reset` tokens. The store also now **fails closed on database errors**: with a database configured, a find error reads as not-found, a delete error loses the consume, and a persist error raises, instead of silently falling back to a per-worker in-memory dict that made a token consumable once per replica. Documented in the `jac-sv-multi-user` skill. Fixes #8461.
