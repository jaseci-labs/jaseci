- **Container move-in for str elements under `--gc none --enforce-nogc`**: owned containers of `str` are now first-class in zero-RC modules. `xs.append(f"x{i}")`, set `add`, dict literals, and `d[k] = v` all work: fresh strings (f-strings, concats, slices, call results) move into the container, named bindings and string literals are copied in (the source stays live and usable, no use-after-move), and dict keys are copied inside the set helper so any str key is safe. Headerless containers carry per-instance element-drop slots stamped at creation, and the container drop now frees the elements it owns (also fixing the silent element leak of comprehension-built `list[str]` and `str.split` results). Borrowed (`&str`) and obj-field-read strings stay fenced with an explicit-copy hint; containers of archetypes and nested containers remain on the ownership roadmap. Also fixes a headerless codegen crash when emitting set/dict helpers for pointer elements (`{"a": 1}`, `st: set[str] = set()` previously died on a null RC-retain reference), and W6002/W6004 no longer flag user-declared methods and fields (`.parse()`, `.assign()`, `.push()`, a `length` field) that merely share a JS-idiom name: resolved symbols are exempt, name-only matching applies to unresolved receivers only.
