- **Breaking: `Anchor.id` is `UUID | None` until something persists the anchor**: A node or edge that has never been connected to a root and never reached a store no longer mints a `uuid4()` up front — identity is what persistence needs, and persistence has not happened yet. `anchor.id` reads `None` for such an anchor, and `anchor.access` is `None` rather than an empty `Permission`. **Jac code that reads `.id` on an anchor it has not persisted, or passes it somewhere a `UUID` is required, now fails to type-check.** Where the anchor really is being persisted, say so: `anchor.ensure_id()` returns the key, minting it if this is the moment one is needed. `jid()`, `save()`, serialization, store writes and edge-row endpoints all call it for you, so only direct `.id` reads are affected. Anchors that grant access take their own `Permission` through `anchor.own_access()`; mutating `anchor.access` in place is no longer how a grant is written. Identity is otherwise unchanged: an anchor that reaches a store gets a uuid at that moment and keeps it, and `__hash__` / `__eq__` fall back to object identity only while there is no key to compare.
