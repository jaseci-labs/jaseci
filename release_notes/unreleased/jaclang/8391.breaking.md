- **Breaking: a port passed to `jac start` is now a contract instead of a preference**: `--port` and `--api_port` used to mean "start here and walk upward if it is taken". jac would bind the next free port, print an ordinary ready banner and exit 0, so a reverse proxy, container port mapping or health probe kept addressing the port that was asked for while the app answered somewhere else. That is how a production preview stayed dead for 12 minutes with every signal green: a supervisor restarted `jac start -p 8000 --dev`, 8000 was briefly still held by the previous run, and the app came up on 8002 behind a proxy pinned to 8000 (#8387). A port the caller names is now honoured or refused: if it is taken, startup fails and the error names the port. Strictness follows whichever port was actually named, so `--port` governs the app port and `--api_port` the API port, independently. This follows the port being named, not the flag being typed, so `[serve] port` in `jac.toml` counts too and governs `jac start` and `jac dev` alike: a project that pins 3000 in config gets a failure rather than a silent move to 3001, which is the point when something downstream (a proxy, an OAuth callback, a hardcoded URL) is addressing 3000. `--api_port` has no config key and stays command-line only. **Leaving a port unset is unchanged** and still relocates with a warning, so the default `jac start` experience does not move. If you pass a port you do not actually depend on, stop passing it: the relocation you were relying on now has to be requested by omission. The two duplicate port finders behind this (`_find_available_port` in scale/server and `_find_free_port` in the CLI) are merged into one `find_available_port` in `runtimelib/net.jac`; the merged version also recognises errno 48, which the scale copy lacked, so port relocation works on macOS for the first time.
