- **Breaking: a named port is now a contract**: if `--port`, `--api-port`, or a project kind's `[serve] port` names a port that is already taken, serving fails and names the port instead of quietly relocating to the next free one; leaving the port unset is unchanged and still relocates with a notice. This holds on both serving paths, including microservice projects (any project declaring `[scale.microservices.routes]`, which is what `jac create --kind web-app` writes), whose gateway previously walked off a pinned port. Two limits worth knowing: a `[scale.microservices] gateway_port` set in `jac.toml` does **not** pin, unlike `[serve] port` on the plain path, because the loaded config merges a default for that key and nothing downstream can tell a chosen 8000 from an assumed one; and mobile/desktop client targets are not covered.
- **The gateway announces the port it bound, not the one it asked for**: the microservice startup banner printed the requested port before binding, so a relocated gateway advertised an address nothing was listening on. It now prints on bind. Every serving path reports a taken port with the same wording, `Port N is already in use`, instead of a raw traceback on some of them.
- **An explicit `--port 8000` is honoured on microservice projects**: it was previously discarded as indistinguishable from the default, so a `gateway_port` in `jac.toml` silently won over the typed flag.
