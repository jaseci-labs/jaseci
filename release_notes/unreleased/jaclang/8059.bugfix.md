- **TypeCheck: an assignment whose RHS is a ternary or a short-circuit chain is visible to flow narrowing again**: `value = a if c else b;` at the end of a block (an `if` arm, an `elif` arm, a `while` body, a `try` body) never reached the statement after that block, so the write was invisible to the narrowing walk and every later `is not None` guard resolved against the pre-block view of the symbol. The symptom was E1053 on the guarded variable *inside its own guard*, reporting the declared union with `| NoneType` still in it. The cause is the CFG, not the walk: `exit_if_else_expr` and `exit_bool_expr` hang the sub-expression graph of a ternary or a short-circuit chain off the statement that holds it, so such a statement carries a `bb_out` whose every edge lands back inside itself (the ternary's arms are dead ends). `_connect_tails`, which carries a block's tail statement to whatever follows the block, tested for *any* outgoing edge and read that as "already wired". It now tests for an edge that **leaves** the statement, and emits the fall-through otherwise. Conditional statements keep the old test: `if a and b { ... }` links only to the short-circuit chain's entry, steering through exactly such an inward edge, and its arms are connected by `_connect_tails`' own recursion.
- **TypeCheck: unions assigned in an unreachable arm are checked again**: the same missing edge silently dropped diagnostics. Where one arm of an `if`/`else` ended in a ternary assignment, that arm's write never reached the join, so the walk saw only the other arm's type and a genuinely bad use of the union checked clean. Those uses are now reported, against the narrowed union.
