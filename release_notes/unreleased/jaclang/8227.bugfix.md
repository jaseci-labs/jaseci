- **Fix: a `from` import of an unlowerable Python module is refused instead of silently miscompiled**: the native capability gate classified only the `import mod;` spelling, so under forced-native placement a `from` import was waved through without being examined at all. `import from threading { Event }` with a class over `Event` therefore lowered to a class with everything it inherits quietly missing -- a wrong binary in place of the refusal the bare import of that same module already gives. A `from`-import item is now classified on the same terms: a name its module publishes as compile-time (`ABC`, `cast`, `TypeVar`, `TypeAlias`) is compile-time, a lowered-stdlib or na_stdlib-shimmed module is a native dependency, and an import resolving to Jac source registers as one, while anything else is a violation that demotes its owning function or refuses the module exactly as the bare spelling would. The vocabulary stays per name rather than per module, so `import from abc { ABC, abstractmethod }` still refuses. Inferred placement, which read the module through `imp.from_loc` and never had the hole, is unchanged.
- **Fix: a `TypeAlias` import no longer blocks native placement**: native glob lowering already skipped `glob Name: TypeAlias = ...` as a compile-time declaration; the `import from typing { TypeAlias }` in front of it was all that still demoted the module, and through the import closure every module reaching it. The marker now lives beside the other compile-time typing names in `codeinfo` rather than being spelled a second time in the codegen pass.
