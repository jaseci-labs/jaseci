- **Fix: JSX children are checked as part of the component contract instead of vanishing**: the client codegen destructures a component's declared parameter names out of `props` with no rest element, so children handed to a component that never declares `children` were dropped with no runtime signal -- a blank render behind a clean `jac check`, a successful build and a silent console. Three diagnostics now cover the shapes that produce it. `W1053` reports children passed to a component that declares no `children` parameter, at the call site that passes them; a component taking a lone `props` bundle receives them as `props.children` and is not flagged. `E1108` blocks a `pages/` project whose exported `app` declares no `children`: the generated entry renders `app` with the whole route tree as its children, so such an entry discards every route and the app renders one stale page forever -- previously documented as a footgun rather than checked, and now keyed on the same `has_pages_dir` predicate that switches file-based routing on, so the check and the behavior cannot drift. `E1109` rejects a `props` bundle declared alongside any other parameter, a shape with no coherent lowering: written positionally the emitted destructure is `const {props, tone} = props`, which is not valid JavaScript, and written keyword-only the component is emitted with a positional signature the renderer never calls that way, so every other parameter silently keeps its default. Which declarations these reach is now decided by one predicate shared with the codegen's call-ABI choice, so `JsxPage`, `JsxLayout` and unions -- the annotations every `pages/` route module uses -- are covered exactly as `JsxElement` is, and the runtime's own `__jac`-prefixed helpers, which are called directly rather than through the props protocol, are exempt in both. Zero-parameter components also stopped being exempt from prop validation, so an undeclared attribute on one is an error rather than accepted without a word -- and because reaching them meant validating elements that carry no attributes at all, JSX prop validation now skips a component element's opening and closing tag nodes, which the parser keeps alongside the complete element. Validating a tag node treats it as a call site passing nothing, so `<Card title="Hi">hello</Card>` reported the `title` it plainly passes as a missing required prop (`E1102`), for any component whose props have no defaults.
- **Fix: a Solid `element=` parent route hands its matched child to the element**: `Route` wrapped an `element=` route's node in a props-ignoring lambda, so the matched nested route never reached it and a parent-route guard rendered nothing -- the mirror image of the React defect, and the same blank page with no error anywhere. The wrapper now provides the matched child through the outlet context, and `AuthGuard` falls back to `<Outlet />` only when it is given no children, so the wrapper, parent-route and layout forms all render.
