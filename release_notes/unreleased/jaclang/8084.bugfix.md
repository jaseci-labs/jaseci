- **Native: every marshalled field of a class with a vtable read its neighbour**: `build_ctypes_classes` mirrored a native struct by appending the layout's named fields in order, never consulting `NativeFieldInfo.index`. The named fields do not cover every slot -- `LayoutPass._build_layout` reserves slot 0 for a vtable pointer on any class that has a parent, is a parent, or is an `isinstance` target, and a second slot for an OSP archetype's type tag -- so the first named field of such a class carries `index == 1` (or `2`), while the mirror placed it at byte 0. Every field of every such struct came back one machine word low: a Python caller reading `obj.x` got the vtable pointer, `obj.y` got `x`, and so on down the struct, as a well-typed wrong value that nothing diagnosed. Slots no `has` names are now mirrored by a pointer-sized filler, so a field's byte offset matches its layout slot. Classes with neither a vtable nor an OSP tag were unaffected, which is why the existing marshal fixtures never caught it. Surfaced while sealing the native parser, where `Module._in_mod_nodes` read `__sub_node_tab` and a parse of an empty module reported 0 nodes against the bytecode parser's 2.
