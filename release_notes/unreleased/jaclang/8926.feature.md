- `by llm` abilities can now be told how their result is consumed downstream: a new use-site analysis follows the result to the single call that receives it and records the consumer's name and semstr, the receiving parameter's name, semstr and type, and any fields read off the value, which the runtime renders as a short "Downstream use" block in the prompt. Off by default, and selectable through `[plugins.byllm.optimizations] use_site_specialization` or `BYLLM_USE_SITE` as `off`, `signature`, `semantic`, or a length-matched `generic` control that carries no downstream information; the `off` path leaves the prompt byte-identical. Setting `BYLLM_USAGE_LOG` additionally appends one JSON record per call carrying the scope, the active mode, the rendered block's token count, the consumer name and the usual token and cost fields.
