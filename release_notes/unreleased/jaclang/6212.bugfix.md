- **Fix: `type(x) is <T>` no longer compares a `typeof` string against a type object in jac2js (#6149)**: On the JS backend, `type(x)` lowered to `typeof x` while the type operand lowered to the tagged constructor `_jac.types.<T>`, so `type(x) is str`, `type(x) is not dict`, etc. were always false (and on older builds, referenced undeclared globals). Exact-type compares now lower to a runtime `_jac.builtin.type_is(x, T)` helper: builtin typenames compare runtime tags with no subclass folding (`type(True) is int` is false, unlike isinstance), and user archetype types compare constructors exactly (not subclass-inclusive `instanceof`). The subject is evaluated exactly once, keeping side-effecting subjects like `type(items.pop()) is dict` correct. The shared `_jac.poly._typename` helper now also classifies plain object literals as `dict` (Jac dict displays lower to bare object literals), which fixes dict classification for `isinstance`/attribute errors too.
