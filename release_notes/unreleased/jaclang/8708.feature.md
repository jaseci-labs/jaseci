- **Build: the native seal fuses into one artifact and one compile**: The seal used to build fifteen separate shared libraries, one per native root, each carrying its own copy of the whole compiler closure, supervised by a pool of worker processes sized by `JAC_SEAL_JOBS` and backed by CI swapfiles. All of that is gone. A generated fused root imports every served module, so the seal now runs two compiles in one process (a unitree layout stage that the materializer root is generated from, then the fused root) and emits a single `libjac_compiler` library plus one layout covering the whole closure. The manifest's native record becomes one artifact plus a served-module list (manifest format 7), the runtime binds the library exactly once (one `__jac_shared_init`, one copy of every native global instead of fifteen), and roughly 120 MB of duplicate per-root artifacts disappear from every payload. The per-root reuse index (`SEAL_INDEX.json`), the worker-pool machinery, `JAC_SEAL_JOBS`, and `--seal-skip-reused-canary` are deleted with it: every seal is a fresh build of the one artifact, and the load, JCIR container, and parse/prefix parity canaries all run against it on every seal.
