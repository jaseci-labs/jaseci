- **Native LLVM IR type equality is now total**: `VectorType`, `ArrayType`, `LiteralStructType` and `IdentifiedStructType` in the vendored IR port returned `None` from `__eq__` instead of `False` when compared against a different type class, because the `isinstance` branch was the whole function body. `None` is falsy, so ordinary guards were unaffected, but any expression that combined two such comparisons boolean-wise saw `False != None` as `True` and took the wrong branch. The array and vector cases also leaked through same-class compares, since both delegate to their element compare. All four now return `False`, which also repairs three declared-`bool` contracts in the native IR-gen pass (`_is_bytes_value`, `_is_bytes_type`, and the `is_str_key` local in the hash-core helpers) that could previously hand back `None`.
