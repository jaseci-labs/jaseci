- **Fix: `jac run <file>` no longer commandeers the project the shell happens to be standing in**: config discovery started at the named file's own directory, and when that found no `jac.toml` it left the config singleton empty -- so the very next bare `get_config()` re-discovered from the *working directory* and handed the one-off script the surrounding project's plan, project root and `.jac/` output tree. Against a running dev server that recompiled the project's client entry to the script and broke every page with a missing-export error. A named file now runs under the project that owns it (the nearest `jac.toml` at or above the file); a file that owns no project runs standalone no matter where the shell is. The decision is stated in one line whenever it could surprise, and `--takeover` / `--no-takeover` override it. `--takeover` keeps its session-eviction meaning when serving, and is no longer treated as a serving-only flag.
- **Fix: dev mode serves the routes `@restspec` declares**: a path such as `/install.sh` returned the SPA HTML shell under `jac run --dev` while `jac run --serve` served it correctly. The Vite dev proxy forwarded a fixed list of prefixes, so every other path fell through to Vite's SPA fallback; the dev server now declares the paths `@restspec` claims to the proxy. The core server, for its part, read `@restspec` only to log that it was ignoring it -- in a message that pointed at the very mode printing it -- and now builds the declared method and path, honoring `produces` / `envelope` by returning the raw payload with that media type while keeping the default `POST` route. The warning survives only for the surface the core server genuinely does not build: path parameters, websockets, webhooks and broadcast.
- **Fix: the dev API port answers unknown paths instead of hanging on them**: the core server's `GET` catch-all rendered the SPA, and in dev that render kicked off a cold production client build (`bun install` plus a full Vite build) inline in the request thread, untimed and under a lock, so the request never got a response head. In dev the client belongs to the Vite dev server, so the catch-all now serves assets and answers `404` for everything else.
- **Fix: HMR re-emits wasm when a native module changes**: modules the client imports natively were compiled to `/static/<stem>.wasm` once, at startup, so editing native code needed a server restart. The watcher now re-emits when a tracked module (or any module declaring native code) changes and asks the page to reload, since a fresh wasm binary is only picked up on a full load. Module classification gained a third answer, native, so a pure `na` module is no longer misread as server code.
- **Fix: a page added or removed during a dev session reaches the browser**: `_routes.js` was regenerated, but the router in the open page had captured its route array at mount, so a new URL kept rendering nothing until the server was restarted. A rewritten route table now raises the same full-reload signal an export-set change does; editing a page body still hot replaces.
- **Fix: bare `jac test` walks the project root when no `[test]` scope is set**: with neither a positional path nor a `[test] directory`, the no-argument default resolved to an empty root, collection skipped it, and the run exited 5 in a project full of suites -- contradicting both the command's own `jac test` example and the config reference. The fallback is the project root (the working directory when there is no `jac.toml`), entered the way a positional path target is, so the usual naming rules and ignores apply and a declared `[test]` scope still wins.
