- **An edges-only reference counts edges, not endpoints**: `len([edge n -->])` pushed its count down as `count(DISTINCT <node>)`, so two parallel edges to the same node counted as one. The count now targets the edge when the reference is `edges_only`, and count and existence checks route through the same resolver the reference itself uses.
- **A traversal is still evaluated where it appears**: the query-answering path (a count, a first row) is now used only where the reference is read on the spot -- `len([a-->])`, `if [a-->]` -- so a reference bound to a name keeps holding the graph as of the line it was written on, as documented. A later attach is not in an earlier reference's result.
