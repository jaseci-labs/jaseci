- **Native backend consumes the core analysis as its single source of type truth**: the LLVM backend no longer keeps a private type model. The checker now persists the facts it computed but discarded (argument-to-parameter binding and the chosen overload on `FuncCall.resolved_callee` / `arg_params` / `type_var_bindings`, the resolved dunder on `BinaryExpr` / `CompareExpr` / augmented `Assignment`, `Ability.is_generator`, `Parameter.ownership`, `CallKind.MODULE_FUNCTION`, a uniform `Expr.narrowed_type`, every `Ability`'s `FunctionType`, typed match-capture names, range-slice operands, parameter defaults, except binders, and expected-typed empty container literals and constructor calls in every position, `ClassDetailsShared.is_native_erased`, the stored native capability partition); `LayoutPass` is scheduled (`PROVIDES layout`) and seeded from `ClassType`; and native lowers from those facts through one `TypeBase` predicate seam. Its guarded `type_system` imports and silent `i64` fallbacks, the mangle-string parsers, the LLVM-value type sniffing, the annotation re-resolution, the private flow-narrowing walker, TypeVar unifier and argument binder, the fabricated default-argument helper, and the name-keyed layout/enum/vtable/return-type mirrors are gone. Fixes #8539.
- **Checker facts the backend now leans on**: member access on a union receiver specializes every member (folding `@overload` siblings through one helper shared with the direct receiver paths), a gradual-union callee (`FunctionType | Any`) binds to its one known member, TypeVar substitution dedupes the unions it builds, type arguments reach the backend in instance form, and in native context `sys.stdout` / `sys.stderr` / `sys.stdin` are the na_builtins `File`. Native materializes the `File` helpers for file-typed receivers and `with` managers, boxes tuples and class references into `any`, lowers dict views as lists of their element and class references as name constants, resolves its dependency modules by the same module-name rule the link step uses, recognizes `own T` has-vars through their annotation again, tolerates message arguments to exception constructors, and reports a loud E5092 instead of silently dropping a method call with no native lowering. Core annotations that said bare `frozenset` / `tuple` / `set` now say what they hold.
- **Check-time rules for the type-shaped native gaps**: in native context `jac check` now reports, through the native capability check (E5090), a set element or dict key type with no single native hash slot, a local bound to a value of type None, a tuple loop target over non-tuple elements or of the wrong arity, and a generator nested in another function or a `yield` inside a lambda; a C-library import declaration that carries a body is a static-analysis E5060 instead of a codegen-only report. A bare `list = []` now refines its element type from archetype and enum instance evidence as well as scalars (`xs = []; xs.append(Box())` types `list[Box]`; only `any`/Unknown or None-only evidence keeps it bare). The backend purity gate forbids mangle-string parsing, `except ImportError` guards, and non-prefetch evaluator calls in the backends, and ceilings the LLVM-value type sniffing, registry scans, and private re-inference helpers per file while the clean break burns them down.
- **Merged with the fixed-width numerics contract (#8544)**: the backend derives signedness and overflow checking from the operand types themselves (`_tb_shape`, the checker's `coerce_to`), sized casts, `T.wrap`, `T.MIN`/`T.MAX` and `type(x)` on scalars dispatch by the callee's `ClassType`, and the conversions in the sized mixin are decided from scalar shapes rather than LLVM value types. Along the way the checker gained facts the backend needed: protocol TypeVars bind structurally (`abs(int)` is `int`), `any(...)` in call position is the builtin function, class references inside displays are `type[C]` elements, `struct.unpack` with a literal format is typed from the shared `jac0core.struct_format` parser (which the native `struct` emitter now uses too), members are attributed to their declaring class (so `list(...)`, `set(...)`, `bytearray(...)` validate against their `__init__` overloads), match guards and value patterns are typed, iteration over a union or an `Any` yields the right element type, enum members assign through their class, and bare `list`/`set`/`dict` annotations are `Any`-element containers at the seam. The unitree seal census fell from 230 demoted methods to 26 (main: 37).
- **The type-system and pass seal ledgers go green by deleting blockers**: a plain enum's convertibility is one shared rule (`enum_literal_scalar_name`, read by the evaluator, `LayoutPass`, and the lowering; `int(Member)` accepts through the int protocols only, and a member whose value no fold reached refuses on that member read), class-form `StrEnum` members carry their text through `str()`, f-strings and comparisons, comprehensions over `d.items()` / `.keys()` / `.values()` lower through the dict iterator, tuple displays remember their element types so `(flag, value)` returns box the `any` slot from the element's own stamp, virtual dispatch coerces each variant's result by that variant's declared member type, identity over statically-`any` references compares addresses, a method call whose receiver reads an erased slot refuses on the field, `frozenset()` builds the empty set, and `type[T]` values print the class name they are. The `sys.version_info` guard family moved from `helpers.jac` into `type_utils.jac` (where `unitree` imports at module scope and `sys.hexversion` folds like `sys.platform`), the evaluator imports its expression-key helpers from `expr_keys.jac` directly, and the analysis passes shed their accidental Python-isms (defensive `isinstance(x, (list, tuple))` ternaries over `Assignment.target`, conditional-expression statements, bare `tuple`/`set`/`frozenset` signatures, unannotated `x = None` first bindings). Net: the unitree ledger drops fourteen waivers and adds one, the evaluator ledger drops twenty-eight, and every seal baseline suite passes from source.
