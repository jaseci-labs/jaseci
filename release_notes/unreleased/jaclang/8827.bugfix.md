- **Fix: type-checking a file could wake the whole serving stack**: the type system lives as OSP nodes and edges, and the checker's first edge traversal fell into `JacGraph.refs`, which fetched the execution context just to ask whether a store was involved; `get_context()` builds a full context on miss, and context construction probed the scale plugin and constructed a server `Session` — up to 66 modules under `jaclang.scale`, `jaclang.server`, and `jaclang.data` imported (and, cold, compiled) per check. Separately, boundary-facts import resolution used `importlib.util.find_spec`, which executes parent packages — and, probing `from X import Y` as a submodule, executes `X` itself — turning import *statements* into import *side effects* at compile time. Kernel interrogatives now answer without creating state (`peek_context`, persistent-flag checks on the origin anchors, "no context means no principal" access gating), the resolver walks specs without executing anything, and the transient memory model moves to `runtime.Memory` with `server.Session` subclassing it for persistence. A cold `jac check` compiles 64 modules instead of 227 (~2x faster, ~2.5x less memory), and a new isolation test fails if a single serving module is imported during a check.
