- **A write that did not happen no longer reports success** (breaking): concurrent read-modify-writes on the same node silently kept the last one and returned HTTP 200 to every loser. Anchors now carry a real monotonic `version` column, the upsert refuses to overwrite a row whose version moved past what the writer read, and the commit happens inside the request attempt rather than in a `finally` after the response value was already produced. Measured on the same 20-way probe: previously 20x HTTP 200 with the counter advancing by 1 and 19 writes lost; now 5x 200 and 15x **409 `WRITE_CONFLICT`**, with the counter advancing by exactly the number of successes. Callers that relied on a write silently winning will now see 409 and should retry.
- **`version` was borrowed from `xmin`, which cannot serve as one**: `xmin` is a 32-bit transaction id that wraps, and `VACUUM FREEZE` rewrites it to a constant, so two different row versions could report the same number. Existing databases gain the column on the next `ensure_schema`.
- **Error envelopes honour the code and status their producer set**: the function and walker endpoints hardcoded `EXECUTION_ERROR` / 500, discarding the `error_code` and `http_status` the optimistic-concurrency path had already chosen. A conflict reported as 500 instead of 409.
