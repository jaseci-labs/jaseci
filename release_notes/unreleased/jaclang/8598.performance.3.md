- **`sorted(<traversal>, key=...)` compiles to `ORDER BY`**: A sort key of the form `lambda (x: T) { x.field; }`, its negation, or a tuple of those has an exact `ORDER BY` equivalent, so the compiler folds the whole `sorted` call into the traversal's query instead of materialising the neighbourhood and sorting it in Python. It composes with a bound -- `sorted(t, key=...)[:3]` becomes `ORDER BY ... LIMIT 3` and reads three rows, not the whole hop. A key that is a real computation, or one annotated with a type that is not the hop's node type, does not fold and keeps its object-space sort. Existing code gets the improvement with no edit.
