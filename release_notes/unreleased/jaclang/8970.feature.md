- **Compiler: the compiler's own tree joins the analysis cache**: The self-host program hydrates and persists module interfaces like any other program, so a `jac check`, LSP open or dependency ingestion of a compiler-tree module is served from its interface instead of re-parsing its dependency closure per file. A serial `jac check` over the server subtree goes from 80s to 10s warm, and the retained-tree state that made serial checks fail on files they never touched no longer arises. Interfaces are encoded only inside analysis-driven closures; a codegen compile records dependency rows and placement and leaves the interface to the first analysis that asks for it. Sealed images carry the analysis sections alongside bytecode.
- **Compiler: a cold rebuild after `jac purge` or a compiler edit collects on a budget**: The per-unit full garbage collection that followed every internal compile is replaced by a process-wide budget (every 16 closure releases or 512 MB of peak RSS growth, tunable with `JAC_UNIT_COLLECT_EVERY` and `JAC_UNIT_COLLECT_GROWTH_MB`). A cold rebuild of the compiler drops from about six minutes to under three.
- **Fix: a comptime site reaches through a hydrated dependency**: A `comptime` binding that calls into an imported module worked on a cold run and failed with E0033 after a body edit, once the dependency was served from its interface. A demanded comptime site now loads the real tree of a hydrated symbol, and the `jaclang.comptime` intrinsics are intercepted by module and name.
- **Fix: the self-host program shares the runtime compiler**: Dependency compiles triggered inside the compiler's own program ran on a second, forked `JacCompiler` with its own depth counter, closure options and stub-catalog state, which broke tree-demand propagation into compiler-tree dependencies.
