- **Sealed builds parse natively, full stop** (issue #8039, Track A follow-up): the `JAC_NATIVE_PARSE_TREES` staging flag is retired. Wherever a sealed parser artifact exists, `parse()` and `parse_diags()` serve from it with no bytecode fallback, and an artifact that fails to load, verify, or bind raises instead of silently degrading (wrong-platform artifacts are now rejected by their recorded triple, and every artifact file is sha256-pinned including the new materializer). The piece that closes the loop is **jacmat**, a C materializer compiled at seal time from `jac0core/native_src/jacmat.c`: it walks the native parser's finished tree and rebuilds it as real Python `unitree` objects at about 1 us per node, following each pointer's rc-header class stamp (never the declared layout type, which union erasure makes unreliable) and reproducing bytecode-parsed instances exactly, down to their `__dict__` key sets via a seal-baked field mask. Net effect on the parse stage: 2.9x to 4.1x over the bytecode parser, growing with module size, with byte-identical trees across all 1,410 jaclang sources; the compiler pipeline consumes the materialized trees unchanged. Environments with no artifact at all (dev source trees, platforms the seal skips) keep parsing on the bytecode tier, which also remains the bootstrap that builds the seal. The standalone lexer artifact is retired from `NATIVE_SEAL_MODULES` (the parser artifact subsumed it), every payload CI lane now compiles through the sealed parser and materializer, with a small `test-native-seal` lane carrying the static census and seam-reachability proofs, and the release floor checks now cover every shipped artifact plus the materializer.
