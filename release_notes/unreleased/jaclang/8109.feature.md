- **Sealed builds parse natively, full stop** (issue #8039, Track A follow-up): the `JAC_NATIVE_PARSE_TREES` staging flag is retired. Wherever a sealed parser artifact exists, `parse()` and `parse_diags()` serve from it with no bytecode fallback, and an artifact that fails to load, verify, or bind raises instead of silently degrading (wrong-platform artifacts are now rejected by their recorded triple, and every artifact file is sha256-pinned including the new materializer). The piece that closes the loop is the **jac materializer**: `compiler/native_materialize.jac`, a generated native jac module sealed as the parser artifact's root, whose typed per-class emitters rebuild the parsed tree as real Python `unitree` objects at about 1.6 us per node through CPython C-API clib externs resolved from the host process (ELF lazy PLT binds; a new Mach-O flat-lookup bind opcode in the in-house linker), reproducing bytecode-parsed instances exactly, down to their `__dict__` key sets via the seal's parser-set field mask. No C compiler or Python headers are needed at build time, and the materializer passes through the seal's own demotion and census gates like every other sealed module. Net effect on the parse stage: 2.1x to 3.2x over the bytecode parser, growing with module size, with byte-identical trees across all 1,410 jaclang sources; the compiler pipeline consumes the materialized trees unchanged. Environments with no artifact at all (dev source trees, platforms the seal skips) keep parsing on the bytecode tier, which also remains the bootstrap that builds the seal. The standalone lexer artifact is retired from `NATIVE_SEAL_MODULES` (the parser artifact subsumed it), every payload CI lane now compiles through the sealed parser and materializer, with the census and seam-reachability proofs running as ordinary test cases in those same lanes, and the release floor checks now cover every shipped artifact plus the materializer.
