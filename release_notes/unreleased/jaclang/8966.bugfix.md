- **Fix: a warm analysis cache never serves a class without its members; fleet pods keep their sibling flag; shared volumes are writable**: The interface cache could persist an importer's interface with an imported class recorded as a local record with no scope, which read back as a class without members (`E1030` on declared fields, `E1096`-`E1098` on archetypes) on every later run until `.jac/cache` was deleted. The evaluator interns one shared per class site, and when a module was compiled again in the same program (a runtime import recompiling an analysis-only tree, or a lane building a twin) the new tree's classes kept the collected first tree's scope. The interned shared now follows the tree the program holds, every hub insertion goes through one `install_module` seam that retires the displaced tree's state, a hydrated interface lives one compile closure, and an interface that cannot place a class is refused (`iface_incoherent`) rather than persisted. On Kubernetes, `JAC_SV_SIBLING=1` is a pod env entry instead of an `export` chained onto the `[dependencies.system]` apt step with `&&`, so a failed install no longer sends a fleet pod into local microservice mode with the whole fleet inside it; the apt step is one best-effort statement that reports its failure. A `[scale.microservices] shared_volumes` mount gets the same root init container the bundle volume already had, which hands the mount root to the runtime `jac` user, plus `fsGroup` for backends that honor it.
