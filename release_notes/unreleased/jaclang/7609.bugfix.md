- **Fix: an unreachable `MONGODB_URI` no longer hangs `jac run` and `jac start`**: Mongo clients are now built with a bounded `serverSelectionTimeoutMS` (new `mongodb_timeout_ms` database config key, default 5000, overridable via `MONGODB_TIMEOUT_MS` or `jac.toml`), and the persistence and identity layers each probe once before committing to Mongo instead of discovering the failure one blocking round-trip at a time. Previously a stale URI left `jac run` blocked for two minutes and `jac start` never binding a port; both now fall back to local storage in seconds with a warning naming the URI (credentials redacted). The bound applies to the operational clients too, not just the startup probe: operations that would previously ride out a replica-set failover under pymongo's 30s default now surface errors after `mongodb_timeout_ms`, so raise it if your deployment needs longer failover tolerance. A failed probe is cached process-wide for 30 seconds, so persistence, identity, webhook, and auth-token startup share one timeout hit instead of each paying their own.
