- **Object-Spatial: building and traversing an in-memory graph no longer pays for persistence**: A graph of `node`s that is never connected to a root and never reaches a store is an ordinary in-memory data structure, and it now costs what its topology costs. Connecting was quadratic — the graph kernel's node table hashed its keys in a way that sent sixteen consecutive handles to one bucket and merged their probe runs, so inserting the nth edge walked about half the table: 85us per edge at 2,000 edges, 365us at 8,000, and 100,000 edges never finished. It is now 5.4us / 6.5us / 9.1us at 128,000. Detaching had the same shape, because an edge's row was found by scanning every row ever allocated (102us per edge at 2,000, 768us at 16,000); it is ~3.1us and flat. Each edge also minted three `uuid4()`s and three `Permission` objects and keyed its registries by `str(id)`, which is machinery only a store needs, so an edge cost ~2.2 KB where the user's own data was ~350 bytes; it is now ~1.08 KB, the rest being the archetype, the anchors and the kernel's own row and index slots. Traversal (`[-->]` and friends) no longer routes a rootless, storeless graph through the persistence query planner, its store-key round trip and its access-control checks: ~8.3us per hop, now ~4.1us. Persisted graphs are unaffected — the identity appears the moment persistence needs it and survives the round trip — and the same fixes apply to the JavaScript client runtime, whose driver mints handles the same dense way.
