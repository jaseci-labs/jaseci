- **A deploy is refused when the app's pinned jac and the deploying jac are a minor line apart, and a pod in a cluster no longer starts a database inside itself**: `[project] jac-version` selects the pod image and the seal, but the jac that runs the deploy is what renders the manifests and provisions the database. Nothing compared the two, so a 0.34 deployer would stand up the store its own generation knows for an app pinned to 0.36 and report success. The pod then found no database url and quietly provisioned one inside itself, per replica, on the pod filesystem, where it was lost on the next restart. A cross-minor deploy is now refused up front, naming both versions, before the cluster is touched. In a cluster a pod with no resolvable database url now fails loudly instead of embedding one, unless the app declares `[scale.kubernetes] database_mode = "none"`.
