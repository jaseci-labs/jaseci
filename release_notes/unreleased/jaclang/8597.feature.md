- **The annex weave is part of producing a module, and the crossing takes every source**: the weave used to sit between the parse seam and the pass schedule -- `parse_str` parsed, `load_annex_modules` read the `.impl.jac`/`.test.jac` siblings, `JacAnnexPass` appended their bodies -- so a module with an annex could not ride the sealed crossing at all: `ASTValidationPass` would have run over a tree carrying none of the impl code, and `DeclImplMatchPass` would have had nothing to match. The prefix declined by name (`annex-present`), correctly and permanently, for 114 of the compiler's own 328 modules. Now `prefix_flip.annex_sources` reads the siblings host-side, the filesystem work no native unit can host, and hands the same list to both routes so the crossing and the staged fallback build the same tree. The crossing takes them through an accumulator: `mat_annex_reset` and `mat_annex_push` stash a native parse per annex and `mat_parse_and_run_prefix` drains the stash through `merge_annex_into` before the prefix runs, fixed arity so the existing scalar entry ABI carries an unbounded annex count without a variadic entry (`type_evaluator.jac` has seven). `serves_annex()` gates it the way `serves_prefix()` does, so an artifact predating the multi-source crossing declines quietly instead of arming. `JacAnnexPass`, `annex_pass.jac`, `Module.annex_mods` and `JacCompiler.load_annex_modules` go with it: `annex_mods` was scratch the driver stamped and the pass cleared, read by nothing else, so nothing replaces it, while `merge_annex_into` stays as the shared weave both routes call. Measured on a sealed build, a module with one annex goes from zero native prefix passes to one, the frontier, with two annex sources behaving the same and an annex-free module unchanged. This is breadth rather than depth: more modules reach the frontier, the frontier is still seat one.
