- **Fix: `jac run` on a web-app keeps its dev server, and the local microservice gateway routes the web app instead of 404ing it**: declaring `[scale.microservices.routes]` describes the service cut a project wants when it is *deployed*, but it also silently decided the local topology, so `jac run` on a web-app traded the vite dev server for a gateway where `/`, `/docs/...` and `/walker/...` 404'd, `/cl/app` was raced across every service in registration order (a service still compiling hung the page), `[serve] base_route_app` was ignored, and nothing served the client. The only escape was `[scale.microservices] enabled = false`, which a deprecation warning told you to delete. Asking for the topology is now explicit: `jac run --ms` (or `[scale.microservices] enabled = true`) selects local microservice mode, `--no-ms` (or `enabled = false`) forces one process, and a dev-client run defaults to one process while `jac run --serve` and every deployed path keep the gateway when routes exist. In that topology the entry module's service is the app: when it serves the client it owns the project root, so `/`, `/cl/<page>`, `/static/client.js` and unclaimed client routes are forwarded to it (in dev at its vite dev server, with its own API as the fallback) rather than 404ing or being probed across the fleet in registration order, and `[serve] base_route_app` is honored where it always was. A deployed fleet pod is unchanged: root ownership is the local web-app path only, so a gateway pod still serves the client bundle its image staged. Boot no longer loses routes either: the client-serving service starts and compiles before its peers touch the analysis cache, the rest start in parallel instead of one 60-second `/healthz` wait at a time, a service that is still compiling stays `starting` rather than being written off as unhealthy and dropped from routing, and its `/openapi.json` answer is never cached until it is healthy. Three smaller fixes fell out of running it: `/static` is gateway-owned rather than learnable (every jac service publishes `/static/{file_path}`, so a headless peer was answering the app's generated `client.js` with a 503); a bodiless status is framed as one (a 304 or 204 went out with `Transfer-Encoding: chunked`, which a browser rejects outright, so every revalidated module the gateway proxied failed to load); and a proxied websocket now completes its upstream handshake before answering the client, echoing the subprotocol the upstream selected, so vite's HMR socket comes up once instead of reconnecting in a loop.
- **Stopping a service signals only the process group it launched**: the stop path followed `terminate` with a group signal so a dev app service's vite child is reaped with it; a process the manager did not launch in its own session (a test double, a pidfile from an older jac) shares the caller's group, and signalling that group took down the caller and everything beside it, including a CI runner. The group signal now goes only to sessions this manager created.
