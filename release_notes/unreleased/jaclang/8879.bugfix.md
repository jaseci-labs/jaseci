- **Fix: the local fleet gateway serves the site**: when the workspace's service apps run as separate local processes (`jac run --fleet`, or `[scale.gateway] colocate = false`), the served app is the fleet's root member and owns the project root: `/`, `/cl/<page>`, `/static/client.js` and unclaimed client routes are forwarded to it (in `--dev` at its vite dev server, with its own API as the fallback) rather than 404ing or being probed across the fleet in registration order. A deployed fleet pod is unchanged: root ownership is the local path only, so a gateway pod still serves the client bundle its image staged. Boot no longer loses routes either: the client-serving root member starts and compiles before its peers touch the analysis cache, the rest start in parallel instead of one 60-second `/healthz` wait at a time, a member that is still compiling stays `starting` rather than being written off as unhealthy and dropped from routing, and its `/openapi.json` answer is never cached until it is healthy. Three smaller fixes fell out of running it: `/static` is gateway-owned rather than learnable (every jac service publishes `/static/{file_path}`, so a headless peer was answering the app's generated `client.js` with a 503); a bodiless status is framed as one (a 304 or 204 went out with `Transfer-Encoding: chunked`, which a browser rejects outright, so every revalidated module the gateway proxied failed to load); and a proxied websocket now completes its upstream handshake before answering the client, echoing the subprotocol the upstream selected, so vite's HMR socket comes up once instead of reconnecting in a loop.
- **Stopping a service signals only the process group it launched**: the stop path followed `terminate` with a group signal so a dev app service's vite child is reaped with it; a process the manager did not launch in its own session (a test double, a pidfile from an older jac) shares the caller's group, and signalling that group took down the caller and everything beside it, including a CI runner. The group signal now goes only to sessions this manager created.
- Client builds (`jac build --client`, `jac serve`, the scale pwa target) no longer crash with `AnalysisLedger has no attribute get`; the client codegen target check reads the analysis ledger through its API.
- Constructing the language server in-process no longer sets the root logger to CRITICAL for the whole process (that silenced every later `logging.error` in the same process, including the `/cl/__error__` diagnostic log); the `jac lsp` stdio entry point does the quieting instead.
- **Boot grace is a window, not a first tick**: the health monitor no longer banks failures while the fleet is booting (a service still compiling when the boot wait gave up used to be marked UNHEALTHY on the first monitor tick, the very symptom the grace was for), and a manager that never booted a fleet is not treated as booting forever, so a bare manager can still mark a dead service unhealthy.
- **A `/static/*` miss on the gateway reaches the root member on any topology**: a fleet pod whose image did not stage an asset the page asks for is forwarded to the served app (the one that publishes `/static/{file_path}`) instead of 404ing, so `/static` being gateway-owned never costs a deployed page its bundle.
