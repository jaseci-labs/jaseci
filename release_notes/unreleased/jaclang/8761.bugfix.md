- **Fix: the payload bundles the LLVM shim under its canonical name** (#8729): mkpayload copied the `--shim` file into the payload keeping the caller's basename, but the runtime locator (`_find_shim`) resolves exactly `libjacllvm.so` / `libjacllvm.dylib` / `jacllvm.dll`. The release channel passes the prebuilt shim fetched from the `deps` release, whose basename is content-addressed (`libjacllvm-<platform>-<hash>.<ext>`), so every sealed release build died on the two `import from c` modules with "Could not locate the LLVM shim", and a non-sealing build would have shipped binaries whose native backend cannot find its own shim at runtime. The bundle copy now canonicalizes the basename via `shim_file_name()`, refuses a shim whose extension says it was built for another platform instead of renaming it into a payload it can never load in, and the payload's post-stage strip of the shim (which silently no-oped on a misnamed file) works again. A test locks the contract that the bundled name equals the name the runtime locator resolves.
