- **Type checking is on the critical path of every compilation, and the gate that skipped it burns down**: `CompileOptions.type_check` is gone, along with `JacProgram.compile`/`build`'s `type_check` parameters, `jac build --no_typecheck`, `[precommit] typecheck` and the never-read `[build] typecheck`. Type inference, the checker, and the full analysis suite (static analysis, access, ownership, native and client capability, portability, lint) now run for every module that compiles, so all 114 diagnostic codes those passes own -- previously absent from `jac run`, every `.jac` import, `jac serve`, HMR, the client bundle, publish, and the `jac build` artifact compile itself -- are unconditional. Blocking follows native's rule everywhere: a module-scoped error stops code generation for every codespace, so a type error is a compile failure instead of the runtime crash it used to become. The flag never bought much, because native modules already forced inference and the checkers and client modules already forced inference, while Python/JCIR codegen reads `Expr.type` nowhere; what it did buy was a schedule assembled at compile time from seven option-dependent fragments. That is now one canonical pipeline whose every declared `REQUIRES` is satisfied by an earlier pass in the same list, which retires the runtime topological composition (`resolve_schedule`, `_schedule_into`, `providers_for`) and its `drop_unsatisfiable` mode -- the mode that, when vendored typeshed stubs were missing, silently produced an empty inference schedule *and* silently dropped `OwnershipCheckPass`. Missing stubs now raise `TypeshedUnavailableError` naming the fix. `TypeInferencePass`, its `inference_only` switch, and the deferred-diagnostic stash are deleted, including the `before_pass` walk that reset every `Expr.type` and cleared the evaluator's flow caches so a second run could emit diagnostics: modules that were inferred and then checked were being fully inferred twice. Compiling the compiler's own passes remains the one exemption, because the bootstrap head provides no `cfg` and the analysis stage is skipped there as a unit rather than dropped pass by pass; `jac check` still analyzes that source in full. `jac check --parse_only` is unaffected -- it never calls `prog.compile`, so it is a syntax probe rather than a way to skip type checking. The JIR format version is bumped so every module passes the new gate exactly once.
