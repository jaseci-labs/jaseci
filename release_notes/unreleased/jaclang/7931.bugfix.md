- **Scale: the gateway now routes app-declared REST paths instead of guessing them** (deployed apps 404'd their whole `/api/*` surface): the microservice gateway decided which paths belonged to a backend by matching the first path segment against a hardcoded allowlist (`walker`, `function`, `user`, `sso`, ...). But a backend's path set is app-defined - `@restspec(path="/api/auth/config")` puts a walker or function anywhere - so any route outside that fixed list fell through to the static-file handler and 404'd at the public URL, while the same app answered 200 when run locally under a single `jac start`. Every deployed jac-client app was affected: the page shell loaded and every API call failed. The gateway now learns each service's real route table from the OpenAPI document that service already publishes (the same document the gateway aggregates for `/openapi.json`), matching templated paths on their literal head so `/api/items/{id}` claims `/api/items/*`. The table is read lazily on the first unclaimed path, cached for `[scale.microservices] route_refresh_seconds` (default 30s), and re-read after that - so a redeployed service picks up new routes without a gateway restart, and a service that never publishes a spec degrades to the previous allowlist behaviour rather than worse. Static assets still win over declared routes, the SPA history fallback now runs *after* route resolution instead of swallowing it, and `/openapi.json` aggregation moved onto the same async fetch (it was blocking the event loop on `urllib`). Root-level WebSocket paths resolve through the same table.
