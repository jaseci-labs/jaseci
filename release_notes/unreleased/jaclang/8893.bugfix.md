- **Scale: one declaration owns every `[scale.kubernetes]` default**: the schema table, `get_default_config`, the `has` declaration on `KubernetesConfig`, a per-key literal inside `from_dict`, and each manifest consumer all restated the same defaults, so a declared key could be dropped or re-defaulted at any hop and the outcome was indistinguishable from a key the user never set. That is why a configured admin username never reached the Prometheus scrape config (#8401) and why `min_replicas` / `max_replicas` / `cpu_utilization_target` never reached an HPA (#8850). `to_dict` and `from_dict` now derive from `comptime for f in fields(KubernetesConfig)`, the same idiom `BaseConfig` and the desktop and auth records already use, so a new `has` line cannot drift out of the converters and a key absent from the config simply takes its declared default. The loader's duplicate default block is deleted, and the autoscaler bounds fall back to the resolved config instead of literals of their own. `[scale.kubernetes]` bounds are app-wide, so they now apply to every service in a fleet including the gateway, exactly as `cpu_request` and `memory_request` already did; a per-service `hpa` table still wins. The same PR closes the fail-loud half: `ManifestBuilder._ms_cfg` and `KubernetesTarget._ms_cfg` were two copies of a loader that answered `{}` on any failure, and six more readers layered their own bare `except` on top, so an unreadable `[scale.microservices]` deployed a monolith instead of the configured fleet without a word. One loader now raises naming the file, the section and the cause, and `manifest_builder.jac` goes from eight `except Exception` arms to one. Fixes #8850, #8401, #8451.
