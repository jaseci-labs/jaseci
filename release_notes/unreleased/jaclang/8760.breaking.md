- **`del` no longer conflates removing a reference with destroying a graph object**: every `del X` used to lower to a `destroy([X])` call *and* a Python `Delete`, with nothing deciding which one the programmer meant. `del d["k"]` therefore destroyed the node the entry pointed at, and `del [edge self-->]` did not compile at all, because the second emitted statement was a Python `del` on a call. `del` now classifies its target recursively: an attribute (`o.x`) or a subscript (`d["k"]`, `L[i]`, `L[i:j]`) is a pure Python reference removal and never destroys; a name destroys when it holds a graph object or a collection of them, and also unbinds; every other expression (a call, an edge-ref trailer, a comprehension, a set literal) destroys and does not unbind; a literal target list recurses per element. On every Python-legal target, Jac now agrees with CPython exactly, with the single deliberate divergence that `del <name>` holding a graph object also destroys it, and a differential harness in the test suite enforces that. Two forms change behavior: `del d["k"]`, `del L[i]` and `del o.x` used to destroy the graph object stored there and no longer do (`del L[i:j]` never did, so index and slice now agree), and value targets such as `del [edge a->:E:->]`, `del [a-->]`, `del get_stale_edges()` and `del {e1, e2}` now compile and destroy exactly what the expression yields. `del a, b;` is also accepted now, and destruction across multiple targets is all-or-nothing rather than CPython's half-applied.
