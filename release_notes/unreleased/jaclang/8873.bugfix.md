- **Fix: parallel `jac check` no longer leaks one file's type conclusions into the next file's verdict**: a check worker reuses one program per file, but every dependency the self-host cache owns is retained in a process-global module hub across files, still carrying the `.type` memos the previous file's evaluator wrote on it. Nothing ever scrubbed those memos (the eraser, `clear_type_system`, had no callers), a diagnosed Unknown memo was returned forever once written, and a mid-check cache miss could evict and rebuild a hub module while a running evaluator still held the old object, giving one class two identities. Because file-to-worker scheduling differs every run, this produced random phantom E1032/E1053/E1099 errors in files a change never touched, which vanished on rerun (#8828). The check job now scrubs the self-host program's type memos after every file, and the evaluator verifies a memoized module view still names the live hub module before trusting it.
