- **Fix: the native backend's slots say what they hold, and its AST walks narrow what they touch**: Twenty-two `na_ir_gen` modules carried type errors of three recurring kinds. A slot declared as whatever it was first assigned, when the code later replaces it with something wider: the comprehension key, value and element types start as an `IntType` and become pointers for tuple and struct cases, the tuple and coercion accumulators start undef and are filled by `insert_value`, and the `os` mode slot starts as a constant. A tree walk that duck-types without an `isinstance`, so a connect operator, a filter comprehension, a call trailer or a comparison's left-hand side was read for members its declared union does not have. And external globals filed under `extern_funcs`, which the rest of the backend reads back as `ir.Function`: stderr, argc, argv, the libc stream handles and the per-stream singleton now live in the module's own global table, looked up under the name each was created with. Behind these, `Module.globals` and `get_global` name the `GlobalValue` they hold, `global_values` yields them, `ArgumentAttributes` carries the `type` its own expansion reads, and `na_tuple_owned` joins the other three attributes the backend stamps on `ir.Value`. `sized` narrows once through a single width accessor rather than reading `.width` off the base `ir.Type` twelve times. No runtime behaviour changes.
