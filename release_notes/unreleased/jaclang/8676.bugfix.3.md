- **Fix: a client survives a concurrent stop of the embedded Postgres**: `PgRuntime.ensure` treated a postmaster that was mid-shutdown as either healthy (and burned its full readiness timeout against it) or already gone (and skipped the restart because the pidfile was still alive), so a store reconnecting across a `jac db stop` from another process raised 57P03 instead of recovering. The locked start path now probes readiness briefly, waits out a dying postmaster, and then starts fresh -- measured recovery drops from ~60s (or an error) to a few seconds. The dangling-ref tests also pass `ensure_cb` like production stores do.
