- **Fix: jac2js host constructor calls are type-driven**: Bare calls to JS/Web API constructors in client code (e.g. `TextEncoder()`, `URL(...)`, `WebSocket(...)`) now lower through the existing type-driven path: the callee resolves to a class declared in `js_globals.pyi`, so codegen emits a proper `new` expression. The Reflect.construct name-list workaround and its hand-maintained registry (`JS_HOST_CONSTRUCTORS`/`JS_HOST_GLOBAL_TAGS`) are removed -- adding a constructor now means declaring it in the stub, which also unlocks parameter checking.
- **Added missing host class stubs**: `URL`, `URLSearchParams`, `WebSocket`, `EventSource`, `XMLHttpRequest`, `Request`, `MessageChannel`/`MessagePort`, `Worker`, `BroadcastChannel`, `Blob`, `File`, `FileReader`, `FormData`, `CustomEvent`, `PopStateEvent`, `DOMParser`, `XMLSerializer`, `Image`, `Audio`, `Notification`, `SharedArrayBuffer`, the remaining typed arrays, `WeakMap`/`WeakSet`/`WeakRef`/`FinalizationRegistry`, and `IntersectionObserver`/`MutationObserver`/`PerformanceObserver` are now declared in `js_globals.pyi` with `__init__` signatures, so bare calls lower to `new` and constructor arguments are checked.
- **Error: keyword args on non-constructible client calls**: Bare calls like `Math(min=1)` (or any kwarg'd call whose callee does not resolve to an instantiable class) now report E6010: keyword arguments would lower to a trailing options object the callee does not understand; pass arguments positionally or use `new(Cls, ...)`.
- **Warning W6010 reworked**: W6010 now fires for genuinely unresolved bare calls in client code (names that resolve to no user declaration or host stub), instead of membership in a hand-written constructor list.
