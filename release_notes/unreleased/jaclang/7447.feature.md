- **Perf: Fast-path `jac --version`**: `--version` is now resolved before the full CLI is imported, dropping it from ~1.3s to ~0.5s. Project config, provider, and template initialization is deferred until after help/version exits, so ordinary commands also skip that work.
- **Perf: On-demand feature command loading**: Feature plugins (client/scale/shadcn/byllm) are imported only when needed: all of them for bare/`--help`, just the matching one for `jac setup`/`scale`/`retheme`/`model`, and none for ordinary commands. Routing is centralized in a declarative `FEATURE_COMMAND_MODULES` map.
- **Perf: Manifest-backed CLI routing**: Lightweight invocations (`jac`, `jac --help`, `jac --version`, unknown commands, tombstones) render from a generated command manifest instead of building the full argparse registry or importing every command module. Known commands dispatch through a per-command lazy loader that imports only the selected handler; `jac <command> --help` defers executor/loader imports until after the help exit. Maintain the route table with `jac gen-cli-manifest` (CI enforces freshness via `jac gen-cli-manifest --verify`).
- **Perf: Lazy `jaclang` package init**: `import jaclang` no longer eagerly loads the runtime and compiler (~350ms on warm cache). `JacRuntime`, `JacRuntimeInterface`, and `compiler` remain available via PEP 562 lazy exports, and `cli_boot` routes informational paths through manifest helpers that avoid importing `console.jac` (which would pull in the full runtime via the meta importer). `jac --version` and `jac --help` drop from ~945ms / ~1157ms to ~360ms / ~380ms on a warm dev tree.
