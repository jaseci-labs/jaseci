- **Compiler cache identity is partitioned into producer cones; `running_compiler_digest` is removed**: a module's jir cache key now embeds exactly the compiler cone that determines its bytes. `codegen_cone_digest()` (the frontend/emitter tree, with `compiler/backends/native` carved out and `runtime/`/`lib/` in no produce-cone at all) keys module env fingerprints and the cache generation namespace; `full_compiler_digest()` (the whole internal tree) keys release seals, kernel artifacts, and precompiled payload keys. Callers of the deleted `running_compiler_digest` migrate to one of the two, choosing by what the key protects: emitted bytes, or a sealed image. `JAC_COMPILER_DIGEST_PIN` values now render as `pin:<cone>:<value>`, so pinned generation names change. Existing cache generations are orphaned by the new keying and regenerate on first use; the 14-day TTL sweep removes the old ones, and there is no migration code by design.
