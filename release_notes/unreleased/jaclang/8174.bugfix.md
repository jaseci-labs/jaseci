- **Serve: streamed generators now run under the caller's root**: a `def:pub` (or walker `report`) generator served as SSE executed after the request context was torn down, so its body silently fell back to the boot context's empty superroot: reads saw an empty graph and writes made after a `yield` were never committed. Generator results are now bound to the request's execution context for the stream's whole life; sync producers run on a dedicated per-stream thread (off the shared request pool), the stream's writes commit before the terminating `event: end` frame, and disconnected, cancelled, or erroring streams close their producer promptly on every exit path (one shared `close_stream_like` helper serves the HTTP, SSE, and WebSocket layers). Open streams are now a declared resource: `[serve] max_concurrent_streams` (default `1024`, `0` = unlimited) caps how many may be open per process, and a request past the cap is refused before any bytes are streamed with a typed `503 stream_limit`. Typed manager errors now surface with their HTTP status on both the native and jac-scale servers, so the existing `409 write_conflict` is a real 409 as documented. Webhook walkers that report a generator now stream instead of crashing.
