- **byLLM gains audio input and return-type-driven media generation**: a new `Audio` type carries clips into any `by llm()` call, serializing to an `input_audio` block that reaches OpenAI verbatim and Gemini as `inline_data`. Declaring `Image`, `Audio` or `Video` as the *return* type now asks the model to produce that medium, with byLLM resolving the transport from the model's capabilities: inline on the chat completion where the model supports it (`gemini/gemini-2.5-flash-image`, `gpt-audio`), otherwise the dedicated `image_generation`, `speech` or `video_generation` endpoint. An `Audio` argument returning `str` routes to `transcription` on a speech-to-text model. Video generation is an asynchronous job byLLM polls to completion, bounded by `poll_interval`/`poll_timeout`; a `def` blocks in the poll and an `async def` awaits it. `Image`, `Audio` and `Video` all gained `save(path)`, and `voice`/`audio_format` can be set on the model config or per call. A model with no path to the declared medium raises `ConfigurationError` naming one that has. (#8809)
