- **Fix: native optional narrowing now declines where the checker's proof does not reach**: the flow-narrowing hook added in #7978 trusted the stamped `Expr.type` in three places the type checker's intra-procedural walk does not actually cover, so a use could read a payload where the sv backend raises. Narrowing is now restricted to function-local names -- attributes, module globals and closure cells are excluded, because a callee that sets one to None is invisible to the walk (`clear(c); return c.x + 1` returned 1 natively where sv raised TypeError). A value live across a loop back edge is excluded unless the loop body unconditionally reassigns it before the use, since the walk skips back edges at loop headers (a guarded value rebound at the end of the body returned a stale payload where sv raised TypeError); the common assign-then-guard-then-use loop still narrows with no tag check. Separately, a `case None` arm now folds to false when the subject's lowered type cannot represent None, instead of emitting `fcmp oeq double %subj, null` and failing the module with an LLVM IR parse error -- that also fixes the same crash for a plainly typed subject, which predates #7978. Every declining case keeps the checked unwrap it had before, so a use that raised still raises.
