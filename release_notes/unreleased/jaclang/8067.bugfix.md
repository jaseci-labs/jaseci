- **Native: `isinstance` against an enum class never lowered over a union**: an enum member boxes as its ordinal, so the check lowers to a jacval tag compare exactly when the operand's static union gives that enum sole ownership of the int tag. `_enum_union_tags` decided that by asking each union member `m.is_enum_class` -- the *uncalled* method (`ClassType.is_enum_class` is declared at `types.jac:172`; the same-named `is_enum_class` at `types.jac:139` is a field of the shared details struct). A bound method is always truthy, so every member classified as an enum owning tag 0, the sole-ownership test found a clash in every union of two or more members, and the tag path never fired on a union -- the only shape it exists for. A non-union operand produces a single row with nothing to clash against, which is why it read as working. A second gap fell out of the same loop: a union arm assigned an enum *literal* carries an `EnumMemberType` rather than the enum `ClassType`, and the loop bailed on the first non-`ClassType` member; classification now goes through `EnumMemberType.enum_class`, since both box as the ordinal. `isinstance(spec, Access)` over `Access | AccessNode | None` (and over `Access | bool`, where bool owns tag 7) now lowers and answers correctly for every arm, while `Access | int`, where `int` claims tag 0 as well, is still refused rather than answered with a tag compare that would report `True` for a plain int. The front end feels this directly: `unitree.jac` resolves symbol access with exactly this shape, and its native census drops from 47 seams to 17, taking the sealed parser's whole closure from 93 to 63.
