- **Fix: a failing database is no longer reported as a missing one**: `shared_store` swallowed every exception and returned `None`, so a database that was resolved and reachable but failed while preparing its schema was indistinguishable from no database being configured, and the user manager reported "no `[scale.database]` url / `JAC_DB_URL` resolved" for a URL that was set and valid. The failure is now kept alongside the `None` and surfaced by `shared_store_error()`; identity storage, the websocket backplane, the ops Postgres probe, the state-backend factory and the auth token store all report the real underlying error and the database that failed, with the password masked.
