- **Compiler: markerless codespace edges -- anchors decide cl/sv/na**: Modules are classified by their anchors and every cross-codespace edge is inferred from a plain `import`; the `cl`/`sv`/`na` markers stay as optional intent overrides. Server-anchored modules (Python imports, OSP archetypes, `::py::`) bridge their `def:pub`s over RPC and their objs as wire types; native-anchored modules (clib externs, ownership marks, or deps that have them) make a plain client import the cl→na wasm edge; browser globals (`Date`, `Promise`, `setTimeout`, …) seed clientness alongside JSX and npm string imports.
- **Behavior change -- pure modules are codespace-polymorphic**: In a module with no server anchor, `def:pub` means *exported*, not *endpoint*: it compiles into each importing codespace instead of bridging over RPC. Modules that host real endpoints are server-anchored by construction and keep bridging; to force RPC for a pure helper, use `sv import` or anchor its module.
- **Fix: transitive client pulls no longer break the bundle**: The seeded pull declines items whose closure can never join the browser bundle (Python imports, endpoints, OSP archetypes) and bridges them instead; codespace stamps invalidate a module's stale cached ES output; and the pull stamps every instance of a module the program holds, so call sites and imports can no longer disagree about where a symbol lives.
- **Fix: the wasm path fails loudly**: `compile_to_wasm` auto-promotes markerless targets the way `jac nacompile` does and raises with the na-census demotion reason instead of silently returning no artifact (the silent `/static/*.wasm` 404 class).
