- **Fix: `na`->wasm builds no longer link a stale vendored libc**: `build.zig` compiled the wasm_rt floor only inside the `link_dir == null` branch that also bundles it into the payload, so `zig build -Ddev` skipped it entirely. That is the one configuration whose runtime resolves `.pbs-build/wasm32/libc` directly, which left the only mode that consumes the floor as the only mode that never produces it: a dev checkout kept serving whatever the last distributable build happened to write. A tree that gained `__jac64_realloc` with the native cycle collector (#7149) therefore linked against a floor that predated it, and every project whose native code reached `realloc` failed to emit a module at all, with `Skipped na->wasm ... wasm import '__jac64_realloc' is neither part of the jac_host1 host ABI nor declared by the app`. The floor is now compiled by every build, dev included; only the bundling stays conditional. The wasm_rt sources are declared as step inputs so Zig can tell the step is out of date, and `build-wasm-libc` decides what to recompile from content hashes rather than mtimes, so a checkout that rewrites timestamps without changing bytes is a no-op while an edit that leaves the mtime alone is still caught. `README`/`LICENSE` no longer count as build inputs, so editing one stops invalidating all 107 objects.

- **Fix: a mismatched wasm floor is diagnosed against the floor instead of the app**: the old failure told the reader to "add it to wasm_rt or to wasm_host_abi.jac". Both are wrong: the adapter was already in `wasm_rt/jac_abi64.c`, and `WASM_HOST_ABI` is syscalls only (`write`, `fopen`, `stat`, `clock_gettime`) and holds no allocator by design, since the allocator works on the module's own linear memory and a host-side `realloc` cannot return a valid wasm pointer -- taking the advice would have produced a module that links and then corrupts memory. Three checks replace it. Before renaming a libc declaration to its `__jac64_` adapter, the compiler verifies the loaded bitcode defines the adapters this module actually needs, and names the missing ones plus the rebuild command. The floor now carries a `SOURCES.sha256` manifest, written by the same step that uses it as its incremental-rebuild key, so a floor built from different wasm_rt bytes is refused by name before it can be folded into a module and ship behaviour that no longer matches the source; a floor without a manifest is treated as unverifiable rather than wrong, so older and hand-built floors keep linking. The linker also recognises an unresolved `__jac64_*` import as a floor adapter and says so, rather than suggesting the host ABI. `na`->wasm had no CI lane at all, which is why an adapter gap could only surface in a user's project; the suite now runs in `test-native-macos`, covering both the source contract and the built bitcode.
