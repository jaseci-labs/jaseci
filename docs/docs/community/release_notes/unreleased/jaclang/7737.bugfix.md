- **Imported na modules inherit the parent's gc options**: the cross-module import walk compiled `import from <sibling>`-ed native modules under default gc "cycles" no matter what the entry was built with, so a `[gc] default = "none"` multi-module program could never come out zero-RC on any path -- the sibling bodies re-entered the RC world and the wasm build's IR audit rejected the artifact. The sub-compile now carries the parent's `na_gc_mode` and nogc enforcement set, and the on-disk cross-module IR cache keys on the gc signature as well, so a cycles-mode compile can no longer poison a later gc-none build of the same sources. This is what lets jaclang.org's shooter ship as one zero-RC wasm linked from four borrow-checked na modules.

- **na module init failures no longer stick**: `@jac/wasm_host` cached the in-flight instantiation promise unconditionally, so a failed fetch or a call made before `set_na_env` left the module permanently broken until page reload. A rejected initialization now clears the cache and the next export call retries.

- **Colliding na import basenames are a build error (E5083)**: two `na import` targets in different directories sharing a file stem would both emit `/static/<stem>.wasm`, one silently overwriting the other while both stubs bound to whichever artifact survived. The client codegen now reports the collision with both paths instead.
