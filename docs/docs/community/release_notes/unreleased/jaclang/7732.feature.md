- **`na import`: the cl -> na edge**: client code can now import a native module the way it imports a server one -- `na import from .arena { init, frame }` -- and the one marked import does all the wiring that previously required hand-typed wasm URLs and manual instantiation. It drives emission (the client build compiles the target module to `/static/<stem>.wasm` plus a `.wasm.imports.json` manifest; the module needs no other importer, and wasm gathering is no longer entry-module-only), binds each imported name to a generated stub (`__na_bind` in `@jac/wasm_host`) that lazily fetches and instantiates the module on the first call, and types those calls as async in client code the same way `sv import` endpoint calls are -- `await init()` is the natural shape. On the Python side the import compiles to **nothing**: only a *plain* import of a native module means the sv -> na ctypes crossing, so an `na import` can never execute raylib-style externs under CPython at server start (the crash that previously forced jaclang.org's shooter to live inside `main.jac`). Modules that declare app FFI register their JS implementations before the first call with `set_na_env("<stem>", shim, {"env": {...}})`; an FFI-free compute module needs no ceremony at all. `compile_to_wasm` also stops hardcoding default `CompileOptions`: it resolves `[gc] default` and `[gc.enforce]` from project config (site-built wasm previously always carried the RC runtime regardless of jac.toml), raises with the first pretty-printed diagnostic instead of a silent "no wasm" when enforcement blocks codegen, and under `[gc] default = "none"` audits the IR for `__rc_*`/collector machinery before linking -- a built-in `--assert-no-rc` for the site-build path.

- **The nogc fence no longer fires on clib extern declarations**: a nogc-enforced module could not declare FFI at all -- every parameter of an `import from raylib { def ... }` extern block was swept as an unannotated heap contract position (E1401/E1404), and the native width types were missing from the checker's scalar set, so `def GetFrameTime -> f32` style declarations tripped the fence. Extern declarations are FFI contracts, not ownership-world code: parameters under an import parent are now skipped and `i8..i64`/`u8..u64`/`f32`/`f64` count as scalars (including width-typed locals from extern call results). The fence still fires on regular defs -- a `str` parameter on an app function remains E1401 -- so the idiom is to call externs with string literals directly and keep wrappers scalar-only. Together with the `na import` edge, this is what lets a real program (jaclang.org's shooter: entity pools as index arenas inside one `own Game` handed to JS as an opaque handle) build under `--enforce-nogc --gc none --assert-no-rc` and ship as a zero-RC wasm artifact reached by one marked import.
